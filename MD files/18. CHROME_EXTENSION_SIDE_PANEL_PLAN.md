# Plan 18 - Migrarea extensiei Chrome de la popup la Side Panel

## Scop

Inlocuieste action popup-ul extensiei Chrome cu un Side Panel persistent, afisat langa pagina curenta.

Rezultatul tinta permite utilizatorului sa:

1. apese iconita extensiei;
2. deschida sau focalizeze Side Panel-ul in fereastra Chrome curenta si sa porneasca automat extragerea din tabul activ;
3. continue sa interactioneze cu pagina fara ca interfata extensiei sa se inchida;
4. compare continutul paginii cu reteta extrasa;
5. editeze, printeze sau salveze reteta folosind actiunile existente;
6. extraga ulterior o alta pagina apasand din nou iconita extensiei, fara sa inchida panelul.

Migrarea vizeaza numai popup-ul deschis din iconita extensiei. Ferestrele separate `edit.html` si `print.html` raman ferestre Chrome de tip `popup` in acest plan.

Dupa fiecare pas:

1. arata exact fisierele modificate;

Nu face commit, push, reset, revert, schimbari generale de formatare sau modificari in afara scopului acestui plan fara o cerere explicita.

Daca implementarea necesita schimbarea unui contract stabilit aici, opreste-te si cere decizia utilizatorului inainte de schimbare.

## Motivatia schimbarii

Action popup-ul actual se inchide cand pierde focusul. Acest comportament ingreuneaza:

- compararea retetei extrase cu pagina sursa;
- derularea paginii in timp ce rezultatul ramane vizibil;
- corectarea manuala a datelor dupa inspectarea paginii;
- urmarirea mesajelor de login sau salvare;
- extragerea repetata fara redeschiderea extensiei.

Side Panel-ul este o suprafata Chrome persistenta si redimensionabila, afisata langa pagina. Utilizatorul poate alege in Chrome daca panelul apare in stanga sau in dreapta.

## Surse oficiale Chrome folosite pentru contract

- [Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel): permisiunea `sidePanel`, `side_panel.default_path`, disponibilitate Chrome 114+ si `sidePanel.open()` din Chrome 116+.
- [Action API](https://developer.chrome.com/docs/extensions/reference/api/action): `action.onClicked` nu este emis cat timp exista `default_popup`.
- [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab): accesul temporar este acordat cand utilizatorul invoca extensia si este revocat la navigare catre alt origin sau la inchiderea tabului.
- [Scripting API](https://developer.chrome.com/docs/extensions/reference/api/scripting): injectarea necesita `scripting` plus `activeTab` sau host permission.
- [Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage#property-session): `storage.session` pastreaza date numai in memorie, este disponibil in service worker si in paginile extensiei si este golit la reload, update, disable sau restart de browser.
- [minimum_chrome_version](https://developer.chrome.com/docs/extensions/reference/manifest/minimum-chrome-version): permite declararea versiunii minime compatibile.

## Starea actuala

### Manifest

- extensia foloseste Manifest V3;
- `action.default_popup` indica `popup.html`;
- sunt declarate `activeTab`, `scripting`, `storage` si `identity`;
- nu este declarata permisiunea `sidePanel`;
- nu exista cheia `side_panel`;
- nu exista `minimum_chrome_version`.

### Popup-ul actual

- `popup.html` contine headerul, actiunile, zona de login, statusul salvarii si rezultatul extras;
- `popup.css` fixeaza latimea documentului pentru un popup de aproximativ 468 px;
- `popup.js` este bootstrap clasic si foloseste importuri dinamice;
- `controllers/popupController.js` pastreaza reteta curenta numai in memoria instantei;
- dupa prima extragere, `Extract Recipe` este ascuns;
- un esec de extragere sterge reteta afisata anterior;
- editarea si printarea deschid ferestre separate `900x700`;
- loginul este orchestrat de service worker;
- `Create account` nu mai exista in extensie.

### Service worker

- `service-worker.js` gestioneaza mesajul `LOGIN`;
- nu gestioneaza clickul pe iconita extensiei;
- nu apeleaza `chrome.sidePanel.open()`;
- flow-ul de login continua independent de durata de viata a interfetei popup.

### Teste

- `popupController.test.js` foloseste HTML-ul real si controllerul real;
- testele protejeaza latimea fixa de 468 px si bootstrap-ul popup clasic;
- mock-urile acopera tabs, scripting, windows si storage;
- nu exista teste pentru Side Panel API sau `chrome.action.onClicked`;
- `javascriptCoverageMatrix.md` descrie explicit arhitectura popup actuala.

## Contractul functional tinta

### Deschiderea Side Panel-ului

- `action.default_popup` este eliminat din manifest.
- Clickul pe iconita extensiei declanseaza `chrome.action.onClicked`.
- Handlerul valideaza `tab.id` si `tab.windowId`, deschide panelul global al extensiei in fereastra curenta si apoi publica o cerere tranzitorie de extragere pentru acel tab. Deschiderea foloseste:

```js
chrome.sidePanel.open({ windowId: tab.windowId })
```

- Daca panelul este deja deschis, clickul pe iconita il pastreaza deschis si porneste automat o extragere noua pentru tabul activ.
- Panelul foloseste o pagina locala declarata prin `side_panel.default_path`.
- Extensia declara `minimum_chrome_version: "116"`, deoarece foloseste `sidePanel.open()`.
- Erorile de publicare a cererii sau de deschidere sunt raportate prin `console.error`; nu trebuie sa produca promise rejection neobservat.

Nu folosi simultan `setPanelBehavior({ openPanelOnActionClick: true })` si handlerul explicit `action.onClicked`. Handlerul explicit este ales pentru ca invocarea iconitei sa ramana punctul clar in care se obtine accesul temporar `activeTab`.

### Permisiunile asupra paginii

- Pastreaza `activeTab` si `scripting`.
- Nu adauga `<all_urls>`, `http://*/*` sau `https://*/*` la host permissions.
- Host permissions existente pentru API-ul aplicatiei raman neschimbate.
- Clickul pe iconita extensiei este singurul gest din UI-ul extensiei care acorda acces temporar si porneste extragerea paginii active.
- Side Panel-ul nu contine buton `Extract`, `Extract again` sau `Retry`.
- Daca utilizatorul schimba tabul sau navigheaza la alt origin, apasa din nou iconita extensiei; acelasi click acorda accesul necesar si porneste automat extragerea.
- Daca panelul este deschis din selectorul Side Panel al Chrome, fara invocarea iconitei, nu incearca extragerea si nu afiseaza o eroare de permisiune. Afiseaza starea initiala explicativa stabilita mai jos.
- Paginile restrictionate precum `chrome://`, Chrome Web Store si alte suprafete protejate raman neextractabile.

Mesajul initial cand nu exista inca o cerere de extragere este:

```text
Click the extension icon to extract a recipe from the current page.
```

Mesajul vizibil pentru o pagina restrictionata este:

```text
This page cannot be accessed. Open a regular web page and click the extension icon.
```

Eroarea tehnica originala este pastrata numai in `reportError`/consola.

### Persistenta vizuala

- Side Panel-ul ramane deschis cand utilizatorul da click sau scroll in pagina.
- Rezultatul extras ramane vizibil cat timp instanta panelului ramane activa si nu este pornita o extragere noua.
- Schimbarea tabului nu sterge automat ultimul rezultat bun.
- Un nou click pe iconita sterge imediat rezultatul vechi inainte sa porneasca extragerea pentru pagina curenta.
- Inchiderea explicita a panelului sau inchiderea ferestrei Chrome poate distruge instanta si starea sa in-memory.
- Acest plan nu adauga persistenta retetei curente in `chrome.storage`.
- Ferestre Chrome diferite pot avea instante Side Panel separate.

Reteta afisata este intotdeauna identificabila prin `Source`, deja randat in rezultat. Actiunile Edit, Print si Save se aplica retetei afisate, nu automat paginii devenite ulterior activa.

### Extragerea declansata de iconita

- Inainte de prima extragere, Edit, Print si Save raman ascunse.
- Clickul pe iconita deschide sau focalizeaza panelul, apoi publica o cerere cu un `requestId`, `tabId` si `windowId`.
- Instanta Side Panel din fereastra respectiva consuma cererea si porneste automat extragerea pentru `tabId` primit; nu cauta din nou tabul activ.
- Dupa o extragere reusita, actiunile Edit, Print si Save apar.
- Un nou click pe iconita produce o cerere noua si curata imediat rezultatul anterior. Daca extragerea reuseste, afiseaza noua reteta; daca esueaza, panelul ramane fara reteta si afiseaza numai eroarea.
- O reteta noua reseteaza statusul salvarii retetei anterioare.
- Pentru un utilizator autentificat, Save devine din nou activ pentru noua reteta.
- Doua clickuri rapide nu pornesc doua injectari paralele pentru aceeasi instanta.
- Daca o salvare este deja in curs, cererea noua de extragere este refuzata controlat si utilizatorul este indrumat sa apese din nou iconita dupa terminarea salvarii.

### Transportul sigur al cererii catre panel

Side Panel-ul poate sa nu fie incarcat in momentul action click-ului. Nu te baza pe timeout-uri sau pe presupunerea ca un mesaj trimis imediat dupa `sidePanel.open()` va avea deja un receptor.

- Foloseste `chrome.storage.session`, disponibil prin permisiunea `storage` deja existenta, numai ca mailbox tranzitoriu pentru cererea de extragere.
- Fiecare cerere are o cheie separata, derivata din `windowId` si `requestId`, astfel incat doua ferestre sa nu isi consume reciproc cererile, iar eliminarea unei cereri vechi sa nu poata sterge un click publicat concurent.
- Service worker-ul scrie numai metadatele cererii: `requestId`, `tabId`, `windowId` si timestamp.
- Bootstrap-ul Side Panel citeste cererea corespunzatoare la initializare si asculta modificarile `chrome.storage.onChanged` pentru clickurile ulterioare.
- Panelul elimina sau marcheaza drept consumata cererea inainte de a incepe injectarea, pentru a evita repetarea ei la reincarcare.
- Ignora cererile duplicate, expirate sau destinate altei ferestre.
- Nu scrie reteta extrasa, datele formularului, tokenul sau rezultatul HTML in acest mailbox.
- Reteta curenta ramane exclusiv in memoria instantei Side Panel.

### Eroarea de extragere

- Adauga o zona separata `extractionStatus`, cu `role="status"` si `aria-live="polite"`.
- In starea initiala afiseaza instructiunea de a apasa iconita extensiei.
- In timpul operatiei afiseaza `Extracting recipe...`.
- La succes, `extractionStatus` este golit.
- La esec, mesajul este afisat intr-un chenar rosu.
- Pornirea unei extrageri noi sterge orice reteta afisata anterior si ascunde actiunile sale.
- La esec, rezultatul ramane gol si actiunile raman ascunse.
- Nu afisa buton de retry; mesajul indruma utilizatorul sa apese din nou iconita extensiei.
- Eroarea tehnica este trimisa catre `reportError`.

### Interactiunea dintre extragere si salvare

Side Panel-ul poate primi mai multe cereri de extragere prin iconita in aceeasi instanta. Controllerul trebuie sa pastreze explicit:

- `isExtracting`;
- `isSaving`;
- `isSaved` pentru reteta curenta;
- `isAuthenticated`;
- `currentRecipe`.

Starea actiunilor este derivata astfel:

```text
saveButton.disabled = !isAuthenticated || isSaving || isSaved || isExtracting
editButton.disabled = isExtracting || isSaving
printButton.disabled = isExtracting || isSaving
```

- Nu permite inlocuirea retetei si nici Edit/Print cat timp salvarea ei este in curs.
- Dupa salvare reusita, Save ramane disabled pentru reteta curenta.
- Dupa o extragere noua reusita, `isSaved` revine la false.
- Dupa o eroare de salvare, Save se reactiveaza daca userul este autentificat.
- Edit si Print raman disponibile dupa o salvare reusita.

### Login in Side Panel

- Loginul continua sa trimita mesajul `{ type: "LOGIN" }` catre service worker.
- Nu duplica `chrome.identity.launchWebAuthFlow` in panel.
- Panelul ramane deschis in timpul autentificarii, in masura in care Chrome pastreaza instanta activa.
- Dupa login reusit, reteta extrasa ramane afisata si Save devine activ.
- Dupa login anulat sau esuat, reteta si actiunile publice raman disponibile.
- Nu adauga `Create account`.

### Edit si Print

- `Edit Recipe` continua sa scrie `recipeToPrint` si sa deschida `edit.html` intr-o fereastra `900x700`.
- `Print / Save PDF` continua sa scrie `recipeToPrint` si sa deschida `print.html` intr-o fereastra `900x700`.
- Side Panel-ul ramane deschis in spatele acestor ferestre.
- Acest plan nu muta formularul de editare in Side Panel.
- Acest plan nu muta preview-ul de print in Side Panel.

### Layout responsive

- Elimina latimea fixa `468px` din HTML.
- Elimina `width: 420px` din body.
- Foloseste `box-sizing: border-box` si latime fluida.
- Controalele se pot impacheta pe mai multe randuri.
- La latimi mici, butoanele raman lizibile si usor de apasat.
- Linkurile lungi se rup fara overflow orizontal.
- Imaginea se incadreaza in latimea panelului.
- Zona de login ramane utilizabila la latimi inguste.
- Layout-ul functioneaza indiferent daca Side Panel-ul este in stanga sau in dreapta.
- Nu presupune si nu forteaza programatic latimea panelului; utilizatorul o controleaza in Chrome.

## Decizii de implementare

### Side Panel global pe fereastra

Se foloseste `side_panel.default_path` si `sidePanel.open({ windowId })`, nu o configurare `tabId` specifica.

Motivul este ca interfata trebuie sa ramana vizibila cand utilizatorul interactioneaza cu pagina sau schimba temporar tabul. Reteta curenta apartine instantei Side Panel din acea fereastra si nu este duplicata automat per tab.

### Fara host permissions generale

Planul pastreaza modelul de permisiuni cu acces minim. Utilizatorul invoca extensia pe pagina pe care doreste sa o extraga.

Acest compromis inseamna ca dupa schimbarea tabului sau navigarea cross-origin trebuie apasata din nou iconita extensiei. Clickul deschide sau focalizeaza panelul si extrage automat; nu exista un al doilea click in interiorul panelului. Este preferabil unei permisiuni persistente de citire pentru toate site-urile.

### Iconita este singurul trigger de extragere

Panelul este o suprafata de rezultat si de actiuni asupra retetei, nu o a doua sursa de permisiune.

- Nu exista buton permanent `Extract`, `Extract again` sau `Retry`.
- Action click-ul produce atat grantul temporar `activeTab`, cat si cererea de extragere.
- Deschiderea panelului din selectorul Chrome afiseaza numai instructiunea initiala.
- Reincercarea dupa o eroare se face printr-un nou click pe iconita extensiei.
- Nu se cere permisiune persistenta per site si nu se cere acces la toate site-urile.

### Mailbox tranzitoriu per fereastra si cerere

Cererea action click-ului trebuie sa supravietuiasca intervalului foarte scurt in care pagina Side Panel se incarca. Pentru aceasta se foloseste un mailbox in `chrome.storage.session`, nu mesaje dependente de timing.

Mailbox-ul contine numai intentia de extragere si fiecare intrare este consumata o singura data. Cheile distincte per cerere permit consumarea in ordine fara ca stergerea unei intrari sa elimine o cerere publicata intre citire si stergere. Nu transforma `chrome.storage` intr-un repository pentru reteta curenta si nu schimba regula ca inchiderea panelului poate pierde rezultatul afisat.

### Bootstrap-ul ramane clasic

Migrarea suprafetei UI nu schimba inutil sistemul de module:

- pagina Side Panel pastreaza un script bootstrap clasic;
- bootstrap-ul continua sa foloseasca importuri dinamice;
- modulele de controller, API si autentificare raman ES modules;
- conversia completa la `<script type="module">` este cleanup separat.

### Nume coerente dupa migrare

La final nu trebuie sa ramana fisiere de productie numite `popup.*` pentru suprafata care nu mai este popup.

Redenumirile tinta sunt:

```text
popup.html                         -> sidepanel.html
popup.css                          -> sidepanel.css
popup.js                           -> sidepanel.js
controllers/popupController.js    -> controllers/sidePanelController.js
tests/popupController.test.js      -> tests/sidePanelController.test.js
```

Exportul `initializePopupController` devine `initializeSidePanelController`.

`extractRecipeFromActiveTab` devine `extractRecipeFromTab`, primeste explicit `tabId` din cererea action click-ului si nu executa un nou `tabs.query`. Astfel extrage exact tabul pentru care utilizatorul a invocat extensia, chiar daca focusul se schimba imediat dupa click.

### Launcher si mailbox separate, testabile

Logica de deschidere a panelului este extrasa intr-un modul mic, de exemplu:

```text
sidepanel/sidePanelLauncher.js
```

Modulul primeste dependente pentru:

- inregistrarea listenerului `action.onClicked`;
- apelul `sidePanel.open`;
- publicarea cererii tranzitorii pentru `tabId` si `windowId`;
- raportarea erorilor.

Un al doilea modul mic, de exemplu `sidepanel/extractionRequestStore.js`, izoleaza citirea, scrierea, consumarea si eliminarea cererilor din `chrome.storage.session`.

`service-worker.js` compune dependentele Chrome reale. Bootstrap-ul Side Panel consuma cererile. Flow-ul de login existent ramane separat si neschimbat.

## Limite obligatorii

- Nu adauga `<all_urls>` sau host permissions generale.
- Nu adauga content script persistent in manifest.
- Nu extrage automat la fiecare navigare sau schimbare de tab.
- Nu adauga buton `Extract`, `Extract again` sau `Retry` in Side Panel.
- Nu cere permisiuni din interiorul Side Panel-ului.
- Nu salveaza automat ultima reteta in `chrome.storage`.
- Nu salveaza reteta sau rezultatul extractiei in mailbox-ul `chrome.storage.session`.
- Nu introduce o colectie de retete per tab.
- Nu muta editorul in Side Panel.
- Nu muta pagina de print in Side Panel.
- Nu modifica API-ul de retete, aplicatia Web, Core sau baza de date.
- Nu modifica payload-ul trimis la Cookbook.
- Nu modifica flow-ul criptografic de login sau stocarea JWT.
- Nu reintroduce `Create account`.
- Nu adauga biblioteci sau framework-uri JavaScript.
- Nu foloseste `sidePanel.setPanelBehavior()` in paralel cu launcherul explicit ales.
- Nu foloseste API-uri Side Panel mai noi de Chrome 116 fara a ridica deliberat `minimum_chrome_version`.
- Toate textele noi vizibile in extensie raman in limba engleza.

## Edge cases obligatorii

- Click pe iconita atunci cand Side Panel-ul este deja deschis.
- Tab activ fara `id` utilizabil.
- Fereastra lipsa sau `windowId` invalid.
- `sidePanel.open()` respinge.
- Publicarea sau consumarea cererii din `chrome.storage.session` esueaza.
- Cerere session invalida, expirata sau deja consumata.
- Aceeasi cerere observata atat de listener, cat si de citirea initiala.
- Side Panel deschis din selectorul Chrome fara cerere action click.
- Navigare la acelasi origin dupa acordarea `activeTab`.
- Navigare cross-origin, care revoca accesul temporar.
- Schimbarea tabului fara reinvocarea extensiei.
- Pagina `chrome://`, Chrome Web Store, New Tab sau alta pagina restrictionata.
- Tab inchis in timpul extractului.
- Doua clickuri rapide pe iconita extensiei.
- Action click primit in timp ce Save este in curs.
- Esec de extract fara rezultat anterior.
- Esec de extract dupa un rezultat valid.
- A doua extragere reusita dupa o salvare reusita.
- Login reusit, anulat sau esuat cu reteta deja afisata.
- Server Web indisponibil; extract/edit/print raman publice.
- Side Panel foarte ingust sau foarte lat.
- Link sursa sau imagine cu URL foarte lung.
- Imagine care nu poate fi incarcata.
- Inchiderea si redeschiderea explicita a panelului.
- Doua ferestre Chrome cu instante separate.

## Criterii finale de acceptare

- Un singur click pe iconita extensiei deschide sau focalizeaza Side Panel-ul si porneste automat extragerea in Chrome 116+.
- Action popup-ul vechi nu mai exista in manifest sau in fisierele de productie.
- Side Panel-ul nu contine buton `Extract`, `Extract again` sau `Retry`.
- Deschiderea din selectorul Chrome afiseaza instructiunea initiala si nu incearca sa extraga fara action click.
- Panelul ramane deschis cand utilizatorul interactioneaza cu pagina.
- Utilizatorul poate compara pagina si rezultatul extras side-by-side.
- Un nou click pe iconita poate inlocui reteta in aceeasi instanta.
- Un nou action click curata imediat rezultatul vechi, iar o extragere esuata lasa panelul fara reteta si cu mesajul de eroare vizibil.
- Reteta noua inlocuieste clar reteta veche si reseteaza starea Save.
- Nu exista operatii paralele de extract si nu se schimba reteta in timpul salvarii.
- Paginile restrictionate si erorile de extragere au mesaje clare care indruma utilizatorul sa apese din nou iconita.
- Mailbox-ul session este separat per fereastra, consumat o singura data si nu stocheaza reteta.
- Nu este solicitata permisiune generala asupra tuturor site-urilor.
- Login, Edit, Print si Save isi pastreaza comportamentul functional.
- `Create account` nu este reintrodus.
- Editorul si printarea raman ferestre separate `900x700`.
- Layout-ul Side Panel este responsive si fara latime fixa.
- Testele JavaScript trec integral.
- `git diff --check` nu raporteaza erori.
