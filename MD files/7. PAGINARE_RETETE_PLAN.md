# Plan paginare lista retete si search

## Scop

Adaugam paginare cu 10 retete pe pagina pentru:

1. lista completa de retete;
2. lista de rezultate de la search.

Ordinea de lucru ramane fixa: mai intai lista completa de retete, apoi search-ul.

Fiecare pas este gandit ca o schimbare mica. Dupa fiecare pas, implementarea se opreste pentru verificare si review.

## Reguli de lucru

- Nu incarca toate retetele in controller sau in aplicatia desktop doar ca sa faci `Skip` / `Take` in UI.
- Pentru SQLite, paginarea trebuie sa ajunga in query-urile SQL prin `LIMIT` si `OFFSET`.
- Pentru JSON, paginarea poate ramane in memorie, pentru ca repository-ul JSON citeste oricum tot fisierul.
- Pastreaza rezultatele ca `RecipeSummary`, nu reveni la incarcarea retetelor complete pentru listare.
- Pastreaza filtrarea pe user-ul curent in service si repository.
- Pastreaza ordonarea existenta: `SavedAt DESC`.
- Dimensiunea paginii este 10.
- Pentru fiecare pagina afiseaza doar cele 10 retete ale paginii curente, dar pastreaza si totalul real de retete/rezultate gasite.
- Search-ul trebuie sa caute in continuare in nume, URL, notite, ingrediente si pasi.

## Starea curenta

- Web:
  - `CarteDeBucate.Web/Controllers/RecipesController.cs`
    - primeste separat `IRecipeLibraryService` si `IRecipeImporterService`.
    - `Index(string? searchText)` foloseste `_recipeLibraryService.GetRecipeSummaries()` pentru lista completa.
    - aceeasi actiune foloseste `_recipeLibraryService.SearchRecipes(searchText)` pentru search.
    - `_recipeImporterService` ramane doar pentru importul retetei din URL.
  - `CarteDeBucate.Web/Models/RecipeIndexViewModel.cs`
    - contine lista afisata si textul cautarii.
    - nu are pagina curenta, total, numar de pagini sau marime pagina.
  - `CarteDeBucate.Web/Views/Recipes/Index.cshtml`
    - afiseaza `Model.Recipes.Count`, adica numarul de elemente incarcate in model.

- Desktop classic:
  - `CarteDeBucate.App/ConsoleUI/ClassicConsole/ClassicConsoleRecipeApp.cs`
    - foloseste separat `_importerService` pentru import din URL si `_recipeLibraryService` pentru biblioteca.
    - `ShowRecipes()` incarca toate sumarurile prin `_recipeLibraryService.GetRecipeSummaries()`.
    - `SearchRecipes()` incarca toate rezultatele prin `_recipeLibraryService.SearchRecipes(searchText)`.

- Desktop rich:
  - `CarteDeBucate.App/ConsoleUI/RichConsole/RichConsoleRecipeApp.cs`
    - foloseste separat `_importerService` pentru import din URL si `_recipeLibraryService` pentru biblioteca.
    - `ShowAllRecipes()` incarca toate sumarurile prin `_recipeLibraryService.GetRecipeSummaries()`.
    - `SearchRecipe()` incarca toate rezultatele prin `_recipeLibraryService.SearchRecipes(searchText)`.

- Core:
  - `CarteDeBucate.Core/Services/Import/IRecipeImporterService.cs`
    - expune doar importul din URL: `ImportRecipeFromUrlAsync(string url)`.
    - nu trebuie extins pentru paginare.
  - `CarteDeBucate.Core/Services/Library/IRecipeLibraryService.cs`
    - expune metodele de biblioteca care returneaza `List<RecipeSummary>` pentru lista completa si search.
    - aici trebuie adaugate metodele paginated pentru lista completa si search.
  - `CarteDeBucate.Core/Data/Repositories/IRecipeRepository.cs`
    - expune doar metode care returneaza liste complete.
  - `DatabaseRecipeRepository`
    - poate pagina eficient cu SQL.
  - `JsonRecipeRepository`
    - citeste fisierul complet, apoi filtreaza/ordoneaza in memorie.

## Termeni propusi

- `PageNumber`: pagina ceruta, 1-based.
- `PageSize`: numarul de retete pe pagina. Pentru acest feature: 10.
- `TotalItems`: numarul total de retete sau rezultate gasite inainte de paginare.
- `TotalPages`: numarul de pagini calculat din `TotalItems` si `PageSize`.
- `Items`: cele maximum 10 retete afisate pe pagina curenta.

## Observatii pentru implementare

- In Web, `RecipesController.Index` poate ramane singura actiune pentru lista completa si search, dar trebuie sa primeasca `pageNumber`.
- In Core, este mai clar sa adaugi metode paginated noi decat sa schimbi semnatura metodelor existente dintr-un singur pas.
- Dupa ce toate fluxurile sunt migrate, se poate decide separat daca metodele vechi mai au rost.
- Daca vrei sa reduci riscul, fa commit separat dupa lista completa paginata si alt commit dupa search paginat.
