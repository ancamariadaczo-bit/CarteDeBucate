# Plan 13 - Pregatirea JavaScript-ului extensiei Chrome pentru testare

## Scop

Reorganizeaza codul JavaScript din `CarteDeBucate.ChromeExtension` astfel incat functionalitatile existente sa poata fi testate ulterior, fara sa scrie teste si fara sa adauge infrastructura Node in acest plan.

Planul separa:

- logica pura de validare si normalizare;
- orchestrarea paginilor extensiei;
- accesul la DOM;
- accesul la `localStorage`;
- apelurile API-urilor Chrome;
- navigarea, inchiderea ferestrei, printarea si timerele.

Comportamentul extensiei trebuie sa ramana identic. Scrierea efectiva a testelor apartine exclusiv fisierului `MD files/14. CHROME_EXTENSION_JS_TESTS_PLAN.md`.

## Regula obligatorie de lucru pentru agent

Executa exact un singur pas mic si apoi opreste-te complet.

Dupa fiecare pas:

1. arata fisierele modificate si rezumatul schimbarii;
2. nu scrie teste si nu adauga fixture-uri sau mock-uri;
3. nu adauga `package.json`, `package-lock.json`, `node_modules` sau dependente npm;
4. nu rula teste, build, `npm install` sau extensia Chrome;
5. cere utilizatorului verificarea manuala exacta pentru pasul curent;
6. asteapta rezultatul si aprobarea explicita a utilizatorului;
7. nu continua fara comanda explicita a utilizatorului.

Nu combina pasii si nu face commit sau push fara o cerere explicita a utilizatorului.

Daca separarea cere schimbarea unui contract functional, opreste-te si cere decizia utilizatorului inainte de modificare.

## Domeniu

Pregateste toate cele sase fisiere JavaScript de productie:

- `CarteDeBucate.ChromeExtension/extractors/jsonLdImporter.js`;
- `CarteDeBucate.ChromeExtension/extractors/htmlImporter.js`;
- `CarteDeBucate.ChromeExtension/extractors/recipeExtractor.js`;
- `CarteDeBucate.ChromeExtension/popup.js`;
- `CarteDeBucate.ChromeExtension/edit.js`;
- `CarteDeBucate.ChromeExtension/print.js`.

Extractoarele au deja API-uri publice prin `globalThis.RecipeClipper` si pot fi incarcate ulterior intr-un DOM de test. Nu le transforma in module ES si nu exporta functiile lor private doar pentru testare.

Refactorizarea efectiva este necesara pentru `popup.js`, `edit.js` si `print.js`, deoarece acestea se initializeaza imediat si folosesc direct dependentele browserului.

## Starea actuala

- `popup.js` combina starea retetei, DOM-ul, storage-ul si API-urile Chrome.
- `edit.js` combina logica pura, DOM-ul, storage-ul, navigarea si inchiderea ferestrei.
- `print.js` combina citirea payload-ului, randarea DOM, evenimentele imaginilor, timerele si `window.print()`.
- Scripturile paginilor sunt incarcate ca scripturi clasice.
- Extractoarele sunt injectate ca scripturi clasice prin `chrome.scripting.executeScript`.
- Nu exista controllere initializabile cu dependente explicite.
- Nu exista un modul separat pentru logica pura a editorului.

## Contracte care trebuie pastrate

- Cheia storage ramane `recipeToPrint`.
- Payload-ul pastreaza `name`, `sourceUrl`, `author`, `imageUrl`, `ingredients` si `steps`.
- JSON-LD are prioritate fata de fallback-ul HTML.
- Ordinea fisierelor injectate ramane `jsonLdImporter.js`, `htmlImporter.js`, `recipeExtractor.js`.
- Rezultatul reusit pastreaza `success`, `method` si `recipe`.
- Mesajul de esec ramane `This page does not appear to contain a recipe.`.
- Ferestrele de editare si printare raman popup-uri de `900x700`.
- Popup-ul ramane la latimea de `420px`.
- `Source URL` este obligatoriu si accepta numai URL-uri absolute HTTP/HTTPS cu host.
- `Image URL` este optional si devine `null` cand este gol.
- Proprietatile needitate, inclusiv `author`, sunt pastrate la editare.
- Enter-urile dintre liniile cu text ale unui pas sunt pastrate.
- Liniile complet goale sau formate numai din spatii sunt eliminate dintr-un pas.
- Continutul retetei continua sa fie introdus prin `textContent` sau `value`, nu prin `innerHTML`.
- Pagina de printare pastreaza timeout-ul imaginilor de 10 secunde si intarzierea de 200 ms.

## Principii de arhitectura

### Entrypoint-uri mici

`edit.js` si `print.js` devin module ES mici. `popup.js` ramane un bootstrap clasic mic, conform exceptiei acceptate de mai jos. Fiecare entrypoint:

- obtine dependentele reale din browser;
- construieste callback-uri mici pentru operatiile externe;
- apeleaza o singura functie de initializare din controllerul corespunzator;
- nu contine logica de validare, normalizare sau randare complexa.

### Exceptia acceptata pentru popup

`popup.html` incarca `popup.js` ca script clasic, iar `popup.js` incarca dinamic `controllers/popupController.js` prin `import()` si apeleaza initializarea dupa rezolvarea importului.

Aceasta este o exceptie intentionata de la regula generala a entrypoint-urilor ES. Verificarea manuala a stabilit ca incarcarea `popup.js` cu `type="module"` si import static facea mult mai vizibila fereastra minima afisata temporar de action popup-ul Chrome. Bootstrap-ul clasic cu import dinamic pastreaza comportamentul vizual anterior refactorizarii, in care fereastra minima poate aparea numai pentru o fractiune de secunda.

Exceptia nu muta logica inapoi in entrypoint:

- `popupController.js` ramane modul ES importabil si complet testabil separat;
- `popup.js` pastreaza numai compunerea dependentelor reale si apelurile API Chrome;
- initializarea asincrona a controllerului este parte din contractul acceptat;
- un review sau un test ulterior nu trebuie sa inlocuiasca importul dinamic cu import static fara o noua decizie explicita si verificare manuala in Chrome.

### Controllere initializabile

Fiecare controller exporta o functie de initializare si primeste explicit dependentele de care are nevoie.

Controllerul nu trebuie sa citeasca implicit din `globalThis`, `window`, `document`, `chrome` sau `localStorage` atunci cand acea dependenta poate fi transmisa ca parametru.

### Logica pura a editorului

`editLogic.js` exporta functii care nu acceseaza DOM-ul, storage-ul, navigarea sau API-urile Chrome:

- `isValidHttpUrl(value)`;
- `normalizeNonEmptyValues(values)`;
- `normalizeInstruction(value)`;
- `normalizeInstructions(values)`;
- `parseRecipePayload(recipeJson)`;
- `validateAndBuildEditedRecipe(originalRecipe, formValues)`.

Functiile nu modifica obiectele sau array-urile primite.

### Extractoarele raman clasice

Nu schimba formatul extractoarelor. Ele vor fi testate ulterior prin API-urile publice existente:

- `RecipeClipper.tryJsonLd()`;
- `RecipeClipper.tryHtml()`;
- `RecipeClipper.extractRecipe()`.
