# Plan 23 - URL-ul sursa si pasii optionali pentru retete

## Scop

Permite salvarea si editarea unei retete fara URL sursa si fara pasi, in toate fluxurile relevante:

- schema SQLite si migrarile existente;
- Core, repository-uri, servicii, backup si API;
- formularele si paginile Web;
- aplicatiile Console Classic si Rich.

Un URL completat ramane valid doar daca foloseste `http` sau `https`. Ingredientele, numele si data salvarii raman obligatorii.

## Regula de lucru

Executa un singur pas mic din acest plan, arata fisierele modificate si verificarile relevante, apoi opreste-te si asteapta aprobarea utilizatorului. Nu grupa pasii in aceeasi implementare si nu incepe automat pasul urmator.

Fiecare pas trebuie sa poata fi verificat separat si, pe cat posibil, sa lase solutia compilabila si testele existente functionale.

## Constatari din inspectia initiala

### Baza de date

- `CarteDeBucate.Core/Data/Database/DatabaseScripts.cs` creeaza `Recipes.SourceUrl` ca `TEXT NOT NULL`.
- Cele trei baze locale inspectate, `recipes.db`, `CarteDeBucate.App/recipes.db` si `CarteDeBucate.Web/recipes.db`, au toate `SourceUrl TEXT NOT NULL`.
- Bazele locale contin in prezent 62, 26 si, respectiv, 211 retete. Niciuna dintre retetele existente nu este fara pasi.
- Pasii sunt stocati in `RecipeSteps`. Schema nu obliga o reteta sa aiba cel putin un rand in acest tabel. `StepText NOT NULL` se aplica numai unui pas care exista si trebuie pastrat.
- Concluzie: este necesara o migrare pentru URL, dar nu este necesara o migrare pentru pasi.

### Backend

- `RecipeValidator` respinge in prezent URL-ul gol si lista de pasi goala. Pentru importul din URL este necesara o verificare de calitate separata, deoarece pasii lipsa trebuie semnalati utilizatorului fara a bloca salvarea.
- Repository-ul SQLite poate salva deja zero pasi, dar citirea URL-ului presupune ca valoarea nu este `NULL`.
- Modelele MVC si API au validare `[Required]` pentru URL si pasi.
- Importul de backup considera in prezent doua URL-uri goale drept duplicate.
- Mesajul Web pentru un import incomplet trateaza lipsa pasilor drept eroare obligatorie.

### Web

- Asteriscurile pentru URL si pasi sunt in partialul comun `_RecipeForm.cshtml`, folosit de Create si Edit.
- Nu exista validare JavaScript custom pentru aceste campuri; regulile client sunt generate din modelul MVC.
- Details ascunde deja sursa cand URL-ul este gol.
- Print afiseaza in prezent un link sursa gol si o sectiune Instructions goala.

### Console

- Console Classic si Rich anuleaza adaugarea manuala daca URL-ul este gol.
- Introducerea pasilor permite deja terminarea imediata cu `gata`; validarea Core este cea care blocheaza salvarea.
- Editarea poate goli lista de pasi, dar nu poate sterge un URL existent deoarece valoarea goala inseamna „pastreaza valoarea curenta”.
- Fluxul separat „Importa reteta din URL” trebuie sa continue sa ceara un URL.

## Decizii de implementare

- `Recipe.SourceUrl` si `RecipeSummary.SourceUrl` raman string-uri nenule pentru compatibilitate cu restul aplicatiei.
- Un URL absent este normalizat la `string.Empty` in Core/UI, dar este scris ca SQL `NULL` in SQLite.
- Repository-ul transforma SQL `NULL` inapoi in `string.Empty`.
- `Recipe.Steps` ramane o lista nenula; absenta pasilor este reprezentata printr-o lista goala.
- Un URL necompletat este valid. Un URL completat, dar invalid, ramane respins.
- `RecipeValidator` valideaza regulile obligatorii de salvare: nume, ingrediente si data salvarii. Nu impune pasi pentru nicio sursa de retete.
- `RecipeQualityChecker` este folosit de validarea comuna de salvare pentru nume si ingrediente. Astfel, un import Web fara ingrediente nu ajunge in baza de date si afiseaza mesajul existent pentru date lipsa, iar consolele pot permite completarea manuala inainte de salvare. `RecipeImportQualityChecker` verifica numai pasii; lipsa acestora este returnata ca avertisment, nu ca eroare de salvare.
- Verificarea duplicatelor se executa numai pentru un URL completat; retetele fara URL nu sunt duplicate intre ele.
- Endpoint-ul `GET /api/recipes/exists` si fluxurile de import din URL continua sa ceara URL, deoarece operatiunea lor nu are sens fara acesta.
- Pentru orice URL ne-gol, verificarea duplicatelor ramane obligatorie inainte de salvare. Verificarea din extensia Chrome este un feedback rapid pentru utilizator, iar verificarea din `RecipeLibraryService.SaveRecipe` ramane autoritatea finala si protejeaza inclusiv cererile concurente sau clientii care nu fac verificarea preliminara.
- Extensia Chrome continua sa normalizeze URL-ul paginii, sa apeleze `GET /api/recipes/exists` si sa blocheze salvarea cand raspunsul este `exists = true`, atat in Side Panel, cat si in fluxul Edit.
- In ambele console, adaugarea accepta URL gol. La editare se introduce o actiune explicita pentru stergerea URL-ului existent, astfel incat Enter sa poata pastra in continuare valoarea curenta. Textul exact al comenzii trebuie definit o singura data in constante si acoperit de teste.
- Bazele `.db` locale nu se editeaza manual. Ele sunt actualizate prin migrator, dupa ce migrarea este acoperita de teste si exista backup.

## Criterii de acceptare

1. O reteta poate fi creata si editata fara URL si fara pasi din Web, Console Classic si Console Rich.
2. In Web nu exista asterisc si nici eroare „obligatoriu” pentru URL sau pasi.
3. Un URL gol este acceptat, iar un URL ne-gol invalid este respins in continuare.
4. SQLite permite `NULL` in `Recipes.SourceUrl`, iar retetele fara pasi au zero randuri in `RecipeSteps`.
5. Migrarea pastreaza retetele, ingredientele, pasii, fotografiile, utilizatorii si cheile straine existente.
6. Mai multe retete fara URL pot fi salvate si importate din acelasi backup fara a fi considerate duplicate.
7. Details, Print si consolele afiseaza coerent o reteta fara URL si fara pasi, fara linkuri goale si fara exceptii.
7a. Un import din URL fara pasi ramane salvabil, dar informeaza utilizatorul ca pasii nu au putut fi extrasi si pot fi completati manual.
8. Importul din URL si endpoint-ul de verificare a URL-ului continua sa respinga URL-ul gol.
9. Aceeasi reteta nu poate fi salvata de doua ori cu acelasi URL ne-gol, indiferent daca salvarea porneste din Web, Console, API sau extensia Chrome.
10. Extensia Chrome continua sa verifice URL-ul inainte de salvare si sa afiseze mesajul pentru o reteta deja existenta.

## Pasul 2 - Relaxeaza validarea Core

Modifica `CarteDeBucate.Core/Validation/RecipeValidator.cs`:

- elimina eroarea pentru URL gol;
- valideaza formatul numai daca URL-ul este ne-gol;
- elimina eroarea pentru lista de pasi goala;
- nu relaxa validarea pentru nume, ingrediente sau data salvarii.

Pastreaza `RecipeQualityChecker` pentru verificarea numelui si ingredientelor si foloseste-l in `RecipeValidator`, punctul comun pentru toate salvarile. Adauga `RecipeImportQualityChecker`, care verifica numai pasii extrasi. Cand lipsesc pasi, acesta trebuie sa produca un avertisment pentru utilizator, fara sa invalideze reteta pentru salvare. Adauga teste focalizate pentru nume, ingrediente, pasi optionali si avertismentul de import.

Verifica daca `RecipeStepsRequired` mai are utilizatori dupa pasii ulteriori; nu elimina inca mesajele folosite de alte fluxuri.

Ruleaza `RecipeValidatorTests` si opreste-te.

## Pasul 3 - Acopera contractul MVC optional prin teste

## Pasul 6 - Acopera si actualizeaza contractul API de creare

In teste Web/API, adauga cazuri pentru `POST /api/recipes` cu:

- `steps` omis, `null` si lista goala;

Apoi modifica:

- `CarteDeBucate.Web/Models/Api/CreateRecipeRequestExtensions.cs` pentru a normaliza URL-ul la `string.Empty` si pasii la lista goala.

Nu modifica cerinta URL din `RecipesApiController.Exists`.

Pastreaza filtrarea verificarii de existenta la utilizatorul autentificat curent. Contractul endpoint-ului ramane `{ exists: boolean }` pentru un URL HTTP/HTTPS valid si ne-gol.

Ruleaza testele `RecipesApiControllerTests` si testele de integrare API relevante. Opreste-te.

## Pasul 7 - Blocheaza regresiile de duplicate in extensia Chrome

Nu elimina si nu ocoli verificarea existenta din:

- `CarteDeBucate.ChromeExtension/controllers/sidePanelController.js`;
- `CarteDeBucate.ChromeExtension/controllers/editController.js`;
- `CarteDeBucate.ChromeExtension/api/recipeApiClient.js`.

Adauga sau actualizeaza testele JavaScript pentru a confirma:

- URL-ul este normalizat inainte de verificare;
- Side Panel apeleaza `recipeExistsBySourceUrl` inainte de salvare;
- Edit apeleaza `recipeExistsBySourceUrl` inainte de salvare;
- raspunsul `exists = true` afiseaza mesajul „This recipe is already saved in your cookbook.” si nu apeleaza salvarea;
- raspunsul `exists = false` permite salvarea;
- o schimbare a URL-ului invalideaza rezultatul anterior si declanseaza o verificare noua;
- o eroare sau o conditie de concurenta in client nu poate elimina protectia finala din backend: daca POST-ul este respins ca duplicat, extensia afiseaza eroarea si nu raporteaza salvare reusita.

URL-ul din extensie provine din pagina retetei si ramane obligatoriu pentru acest flux; caracterul optional al `SourceUrl` se aplica formularului manual si contractului general de creare, nu elimina verificarea extensiei.

Ruleaza testele JavaScript focalizate pentru API client, Side Panel si Edit. Daca implementarea curenta trece deja toate cazurile, nu modifica productia doar pentru a produce un diff. Opreste-te.

## Pasul 17 - Verificare finala

Ruleaza:

1. testele Core, DB, repository, backup, Web/API si Console focalizate;
2. intreaga suita `dotnet test`;
3. orice teste JavaScript existente pentru extensie, pentru a confirma ca relaxarea contractului API nu a produs regresii.

Fa apoi verificarea manuala:

1. creeaza in Web o reteta fara URL si fara pasi;
2. confirma ca un URL invalid ne-gol este respins;
3. editeaza o reteta existenta si elimina URL-ul si toti pasii;
4. deschide Details si Print;
5. repeta creare, editare si afisare in Console Classic si Rich;
6. confirma ca Import din URL respinge in continuare URL gol;
7. importa un backup cu doua retete fara URL si pasi;
8. incearca sa salvezi a doua reteta cu acelasi URL din Web, API si extensia Chrome si confirma ca toate fluxurile o resping;
9. confirma ca extensia apeleaza verificarea de existenta inainte de POST si afiseaza mesajul de duplicat;
10. aplica migrarea pe copii de siguranta ale celor trei baze locale;
11. compara numarul de retete, ingrediente, pasi si fotografii inainte/dupa si ruleaza `PRAGMA foreign_key_check`;
12. confirma in `PRAGMA table_info(Recipes)` ca `SourceUrl` are `notnull = 0`.

Nu aplica prima data migrarea pe singura copie a unei baze cu date reale. Pastreaza backup-urile pana dupa verificarea manuala completa.

Opreste-te si raporteaza fisierele modificate, migrarile aplicate, rezultatele testelor si orice risc ramas.
