# Plan 14 - Scrierea testelor pentru JavaScript-ul extensiei Chrome

## Scop

Adauga infrastructura si testele automate pentru toate cele sase fisiere JavaScript de productie din `CarteDeBucate.ChromeExtension`, dupa finalizarea si verificarea planului `MD files/13. CHROME_EXTENSION_JS_TEST_PREPARATION_PLAN.md`.

Acest plan nu reorganizeaza codul de productie. El scrie configuratia de test, helper-ele, mock-urile, fixture-urile si testele efective pentru:

- extractoarele JSON-LD si HTML;
- alegerea strategiei de extragere;
- controllerul popup-ului;
- logica si controllerul editorului;
- controllerul paginii de printare;
- entrypoint-urile subtiri rezultate din planul 13.

## Regula obligatorie de lucru pentru agent

Executa exact un singur pas mic si apoi opreste-te complet.

Dupa fiecare pas:

1. arata fisierele modificate si rezumatul schimbarii;
2. nu modifica logica de productie decat dupa explicarea unui defect si aprobarea utilizatorului;
3. nu rula teste, build, `npm install` sau extensia Chrome;
4. cere utilizatorului sa ruleze comanda exacta de verificare;
5. asteapta rezultatul si aprobarea explicita a utilizatorului;
6. nu continua fara comanda explicita a utilizatorului.

Nu combina pasii si nu face commit sau push fara o cerere explicita a utilizatorului.

Un test trebuie sa verifice contractul existent. Daca rezultatul real contrazice planurile 12 sau 13, agentul se opreste si cere decizia utilizatorului; nu slabeste asertiunea doar pentru ca testul sa treaca.

## Conditie obligatorie de pornire

Nu incepe acest plan pana cand:

- planul 13 este implementat complet;
- utilizatorul a verificat manual extensia dupa refactorizare;
- controllerele si `editLogic.js` pot fi importate fara pornirea automata a browserului;
- `popup.js` ramane bootstrap-ul clasic acceptat, cu import dinamic al `popupController.js`;
- extractoarele raman disponibile prin `globalThis.RecipeClipper`.

Exceptia pentru `popup.js` este contract intentionat, nu defect de corectat in acest plan. Testele nu transforma bootstrap-ul in modul ES si nu inlocuiesc importul dinamic cu import static.

## Tehnologia de testare

Foloseste:

- Node.js LTS;
- runner-ul nativ `node:test`;
- `node:assert/strict`;
- `jsdom` ca singura dependenta npm de dezvoltare;
- mock-uri locale pentru API-urile Chrome si efectele browserului.

Nu adauga Jest, Vitest, Mocha, Chai, Sinon, Playwright sau Cypress.

Node singur acopera logica pura. `jsdom` este necesar pentru testarea DOM-ului folosit de extractoare, popup, editor si pagina de printare.

Pentru popup, separa doua niveluri de verificare:

- importa direct `controllers/popupController.js` si testeaza comportamentul controllerului cu dependente injectate;
- citeste fisierele reale `popup.html` si `popup.js` pentru a verifica static bootstrap-ul clasic, importul dinamic si compunerea dependentelor.

Nu executa `popup.js` ca modul ES in test si nu astepta indirect o promisiune de initializare pe care bootstrap-ul nu o exporta.

## Principii obligatorii pentru teste

- Testele folosesc fisierele JavaScript si HTML reale ale extensiei.
- Nu copiaza algoritmii de productie in helper-ele de test.
- Fiecare test construieste o stare izolata.
- Nu exista dependenta intre ordinea testelor.
- Mock-urile inregistreaza apelurile si intorc numai datele cerute de scenariu.
- Testele nu fac cereri de retea.
- Testele nu deschid Chrome si nu afiseaza dialogul real de printare.
- Timeout-ul de 10 secunde este simulat; niciun test nu asteapta 10 secunde reale.
- Fixture-urile sunt mici si contin numai markup-ul necesar scenariului.
- Continutul potential HTML este verificat ca text, nu executat.
