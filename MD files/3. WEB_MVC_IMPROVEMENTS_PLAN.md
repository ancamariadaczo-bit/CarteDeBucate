# Plan de imbunatatire pentru aplicatia Web MVC

## 1. Scop

Acest document descrie imbunatatirile recomandate pentru proiectul
`CarteDeBucate.Web`.

Planul urmareste:

- navigare mai fireasca dupa creare, editare, import si stergere;
- feedback vizibil dupa actiunile reusite;
- acces mai usor la actiunile importante;
- cautarea retetelor din interfata web;
- formulare mai clare si validare mai apropiata de campurile gresite;
- afisarea statusurilor in limba romana;
- eliminarea elementelor ramase din template-ul MVC implicit;
- un aspect vizual mai coerent cu o aplicatie pentru retete.

Fiecare etapa este impartita in pasi mici. Dupa fiecare pas trebuie verificat
comportamentul descris in sectiunea de verificare a pasului.

## 2. Limitele planului

### Inclus

- proiectul `CarteDeBucate.Web`;
- fluxurile web pentru listare, detalii, creare, editare, stergere si import din URL;
- modele si partial view-uri folosite numai de interfata web;
- ajustari mici in contractele sau rezultatele din `CarteDeBucate.Core` numai
  daca sunt necesare pentru comportamentul web;
- teste pentru controllerele si modelele web.

### Exclus

- orice optimizare sau cerinta pentru mobil;
- responsive design;
- autentificarea;
- importul si exportul backup-ului;
- modificari in `CarteDeBucate.App`;
- modificari in `ClassicConsole` sau `RichConsole`;
- schimbari ale comportamentului vizibil din aplicatia console.

## 3. Reguli pentru implementare

1. Se lucreaza in pasi mici, in ordinea din document.
2. Nu se combina mai multe etape intr-o singura modificare mare.
3. Dupa fiecare pas se actualizeaza sau se adauga testele relevante.
4. Aplicatia console trebuie sa ramana neatinsa.
5. Logica business nu se muta in view-uri.
6. Controllerele coordoneaza fluxul web, iar validarea business ramane in Core.
7. Nu se introduce autentificare sau logica pregatitoare pentru autentificare.
8. Nu se adauga functionalitati pentru backup.
9. Nu se implementeaza variante speciale de layout sau interactiune pentru mobil.
10. Utilizatorul va rula manual comenzile de build, test si run.

## 4. Starea actuala relevanta

Fisierele principale sunt:

```text
CarteDeBucate.Web/
  Controllers/
    HomeController.cs
    RecipesController.cs
  Models/
    RecipeFormViewModel.cs
  Views/
    Recipes/
      Index.cshtml
      Details.cshtml
      Create.cshtml
      Edit.cshtml
      Delete.cshtml
      Import.cshtml
    Shared/
      _Layout.cshtml
      Error.cshtml
  wwwroot/
    css/site.css
    js/site.js

CarteDeBucate.Tests/
  Web/
    RecipesControllerTests.cs
```

Comportamentul actual:

- dupa creare se revine la lista;
- dupa editare se deschide pagina de detalii;
- dupa import se revine la lista;
- dupa stergere se revine la lista;
- nu exista mesaje de confirmare dupa redirect;
- stergerea este accesibila din lista, dar nu din Edit sau Details;
- `SearchRecipes` exista in Core, dar nu este expus in pagina web;
- statusurile sunt afisate cu numele enum-urilor in engleza;
- Create si Edit contin markup aproape identic;
- layout-ul mai contine elemente din template-ul MVC implicit.

## 5. Ordinea generala recomandata

1. Stabilirea baseline-ului.
2. Mesaje temporare dupa actiuni.
3. Navigare catre Details dupa creare.
4. Navigare catre Details dupa import.
5. Actiunea de stergere in Details si Edit.
6. Cautarea retetelor.
7. Afisarea prietenoasa a statusurilor.
8. Imbunatatirea listei si a starii goale.
9. Refolosirea formularului Create/Edit.
10. Validarea formularului web.
11. Protectia modificarilor nesalvate.
12. Starea de incarcare pentru import.
13. Curatarea layout-ului si identitatea vizuala.
14. Pagini de eroare potrivite aplicatiei.
15. Verificarea finala.

# Etapa 4 - Deschiderea detaliilor dupa import

## Decizia pentru aceasta etapa

Fluxul implementat acum va fi:

```text
Import URL -> salvare -> Details -> utilizatorul poate alege Edit
```

Nu se implementeaza in aceasta etapa previzualizarea inainte de salvare.
Aceasta este descrisa separat la final ca imbunatatire optionala.

## Pasul 4.1 - Confirma reteta in rezultatul importului

`ImportFromUrlAndSaveAsync` foloseste deja `SaveRecipe`, iar rezultatul de succes
poate contine reteta salvata.

Pastreaza acest rezultat pana in controller si foloseste:

```csharp
result.Recipe.Id
```

### Verificare

- reteta returnata are ID-ul atribuit de repository;
- controllerul nu cauta reteta dupa URL si nu ia primul element din lista.

## Pasul 4.2 - Schimba redirect-ul dupa import

In POST `Import`, inlocuieste redirect-ul catre `Index` cu redirect catre
`Details`, folosind ID-ul retetei importate.

### Verificare

- dupa import reusit se deschide exact reteta importata;
- ingredientele si pasii importati sunt vizibili;
- URL-ul sursa este vizibil;
- importul esuat ramane in pagina Import si pastreaza URL-ul introdus.

## Pasul 4.3 - Afiseaza un mesaj specific importului

Mesajul trebuie sa explice urmatorul pas, de exemplu:

```text
Reteta a fost importata. Verifica informatiile si editeaza-le daca este nevoie.
```

Nu afisa doar un mesaj generic de salvare.

### Verificare

- mesajul apare pe pagina Details;
- utilizatorul intelege ca datele importate trebuie verificate;
- eroarea de import nu este afisata ca succes.

## Pasul 4.4 - Evidentiaza actiunea Edit dupa import

Pagina Details are deja un link catre Edit.

Pastreaza un singur view Details, fara o pagina separata pentru reteta importata.
Mesajul de succes trebuie sa faca actiunea de editare usor de inteles.

Nu introduce un mod permanent `isImported` in model doar pentru stilizare.

### Verificare

- utilizatorul poate trece din Details in Edit cu un singur click;
- pagina Details functioneaza identic si pentru retetele create manual.

## Pasul 4.5 - Adauga teste pentru import

Adauga teste pentru:

- import reusit cu redirect catre Details;
- ID-ul retetei importate in redirect;
- mesajul temporar specific importului;
- import esuat care intoarce view-ul Import;

# Etapa optionala ulterioara - Previzualizare inainte de salvarea importului

Aceasta etapa nu face parte din implementarea principala de mai sus.

Fluxul tinta ar fi:

```text
URL -> import fara salvare -> formular de verificare/editare -> salvare -> Details
```

Ar necesita:

1. POST Import sa apeleze `ImportRecipeFromUrlAsync`, nu
   `ImportFromUrlAndSaveAsync`.
2. Rezultatul importat sa fie transformat in `RecipeFormViewModel`.
3. Datele sa fie afisate intr-un formular de verificare.
4. Utilizatorul sa poata corecta numele, ingredientele, pasii, notitele si
   statusul.
5. Salvarea sa fie facuta numai dupa confirmarea formularului.
6. Sa existe protectie impotriva pierderii datelor importate intre request-uri.
7. Sa fie stabilit clar daca anularea abandoneaza complet importul.

Aceasta varianta este mai sigura pentru importuri incomplete, dar trebuie
implementata ca flux separat, nu amestecata cu simpla schimbare de redirect.
