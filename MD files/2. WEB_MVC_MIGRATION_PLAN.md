# Plan pentru adaugarea partii Web ASP.NET Core MVC

## Context si obiectiv

Aplicatia existenta este impartita in:

- `CarteDeBucate.Core`: modele, configuratie, validari, repository-uri, servicii, import recipe, autentificare.
- `CarteDeBucate.App`: aplicatia console, cu doua moduri de UI:
  - `ClassicConsole`
  - `RichConsole`
- `CarteDeBucate.Tests`: teste xUnit pentru core si console.

Obiectivul este adaugarea unui proiect web ASP.NET Core MVC, pastrand aplicatia console existenta si posibilitatea de a rula ambele moduri console.

Important: implementarea trebuie facuta cu **MVC: Controllers + Views**, nu Razor Pages.

## Reguli pentru LLM-ul care implementeaza

- Nu elimina proiectul `CarteDeBucate.App`.
- Nu elimina `ClassicConsole` si `RichConsole`.
- Nu muta UI-ul console in proiectul web.
- Nu duplica logica business in controllere sau view-uri.
- Pune logica reutilizabila in `CarteDeBucate.Core` sau intr-un helper comun.
- Fa modificarile in pasi mici.
- Nu rula build, test sau run automat. Utilizatorul le va rula manual ca sa economiseasca tokeni.
- Dupa fiecare etapa importanta, opreste-te si spune exact ce comenzi trebuie sa ruleze utilizatorul.
- Pastreaza target framework-ul existent: `net10.0`, daca SDK-ul local il suporta deja.
- Nu introduce namespace-uri peste tot intr-un pas separat, decat daca este absolut necesar.
- Web-ul trebuie sa foloseasca aceleasi servicii/repository-uri din `CarteDeBucate.Core`.
- `CarteDeBucate.Web` nu trebuie sa aiba referinta catre `CarteDeBucate.App`.

## Rezultat final dorit

La final trebuie sa existe:

- aplicatia console rulabila in continuare;
- modul `ClassicConsole` rulabil prin configuratie;
- modul `RichConsole` rulabil prin configuratie;
- un proiect web nou, de exemplu `CarteDeBucate.Web`;
- proiectul web adaugat in solutie;
- un `RecipesController`;
- view-uri MVC pentru retete;
- web-ul poate lista retete;
- web-ul poate vedea detaliile unei retete;
- web-ul poate adauga o reteta manual;
- web-ul poate edita o reteta;
- web-ul poate sterge o reteta;
- optional, intr-un pas ulterior, web-ul poate importa o reteta din URL.

## Etapa 3 - Extrage configurarea comuna de servicii

Problema actuala: `CarteDeBucate.App/Program.cs` construieste manual repository-uri si servicii. Web-ul va avea nevoie de aceeasi constructie. Nu copia aceeasi logica in `CarteDeBucate.Web/Program.cs`.

### Pas 3.1 - Creeaza un factory comun in Core

Creeaza un fisier nou:

```text
CarteDeBucate.Core/Configuration/AppServiceFactory.cs
```

Scop:

- centralizeaza crearea repository-urilor;
- centralizeaza initializarea bazei de date;
- centralizeaza crearea serviciilor folosite de console si web.

API recomandat:

```csharp
public static class AppServiceFactory
{
    public static void EnsureDatabaseIsUpToDate(AppSettings settings)
    {
    }

    public static IRecipeRepository CreateRecipeRepository(AppSettings settings)
    {
    }

    public static IUserRepository CreateUserRepository(AppSettings settings)
    {
    }

    public static IRecipeImporterService CreateRecipeImporterService(
        AppSettings settings,
        ICurrentUserContext currentUserContext)
    {
    }

    public static IRecipeBackupService CreateRecipeBackupService(
        AppSettings settings,
        ICurrentUserContext currentUserContext)
    {
    }

    public static IAuthenticationService CreateAuthenticationService(
        AppSettings settings,
        ICurrentUserContext currentUserContext)
    {
    }
}
```

Observatii:

- muta in acest factory logica existenta din `Program.cs`:
  - `EnsureDatabaseIsUpToDate`
  - `CreateRecipeRepository`
  - `CreateUserRepository`
- pastreaza comportamentul identic;
- foloseste aceleasi clase existente:
  - `JsonRecipeRepository`
  - `DatabaseRecipeRepository`
  - `JsonUserRepository`
  - `DatabaseUserRepository`
  - `RecipeImporter`
  - `RecipeImporterService`
  - `RecipeBackupService`
  - `AuthenticationService`

Dupa acest pas, cere utilizatorului sa ruleze manual:

```bash
dotnet build CarteDeBucate.App/CarteDeBucate.App.sln
```

## Etapa 4 - Configureaza dependency injection pentru Web MVC

### Pas 4.1 - Configureaza `CarteDeBucate.Web/appsettings.json`

Adauga aceleasi setari de baza ca in consola:

```json
{
  "StorageMode": "Database",
  "InterfaceMode": "RichConsole",
  "RecipesFilePath": "recipes.json",
  "UsersFilePath": "users.json",
  "DatabasePath": "recipes.db",
  "AuthenticationEnabled": false
}
```

Observatie importanta:

- `InterfaceMode` ramane util pentru consola, dar web-ul nu trebuie sa il foloseasca pentru UI.
- In fisierul actual al consolei exista `JsonFilePath`, dar `AppSettings` citeste `RecipesFilePath`. Pentru web foloseste `RecipesFilePath`.

### Pas 4.2 - Configureaza serviciile in `CarteDeBucate.Web/Program.cs`

In `Program.cs` al proiectului web:

- pastreaza configuratia MVC generata de template;
- incarca `AppSettings`;
- apeleaza `AppServiceFactory.EnsureDatabaseIsUpToDate(settings)`;
- inregistreaza `AppSettings` in DI;
- inregistreaza `ICurrentUserContext`;
- inregistreaza repository-uri si servicii.

Programul web trebuie sa contina in continuare:

```csharp
builder.Services.AddControllersWithViews();
```

Varianta simpla recomandata pentru serviciile aplicatiei:

```csharp
AppSettings appSettings = AppSettings.Load();
AppServiceFactory.EnsureDatabaseIsUpToDate(appSettings);

builder.Services.AddSingleton(appSettings);
builder.Services.AddScoped<ICurrentUserContext, CurrentUserContext>();
builder.Services.AddScoped<IRecipeRepository>(_ =>
    AppServiceFactory.CreateRecipeRepository(appSettings));
builder.Services.AddScoped<IUserRepository>(_ =>
    AppServiceFactory.CreateUserRepository(appSettings));
builder.Services.AddScoped<IRecipeImporterService>(serviceProvider =>
{
    ICurrentUserContext currentUserContext =
        serviceProvider.GetRequiredService<ICurrentUserContext>();

    return AppServiceFactory.CreateRecipeImporterService(appSettings, currentUserContext);
});
builder.Services.AddScoped<IRecipeBackupService>(serviceProvider =>
{
    ICurrentUserContext currentUserContext =
        serviceProvider.GetRequiredService<ICurrentUserContext>();

    return AppServiceFactory.CreateRecipeBackupService(appSettings, currentUserContext);
});
builder.Services.AddScoped<IAuthenticationService>(serviceProvider =>
{
    ICurrentUserContext currentUserContext =
        serviceProvider.GetRequiredService<ICurrentUserContext>();

    return AppServiceFactory.CreateAuthenticationService(appSettings, currentUserContext);
});
```

Dupa acest pas, cere utilizatorului sa ruleze manual:

```bash
dotnet build CarteDeBucate.App/CarteDeBucate.App.sln
```

## Etapa 5 - Creeaza MVC pentru retete

### Pas 5.1 - Creeaza un view model pentru formulare

Creeaza:

```text
CarteDeBucate.Web/Models/RecipeFormViewModel.cs
```

Responsabilitate:

- tine datele formularului web;
- evita legarea directa a formularului complex la modelul `Recipe`;
- transforma textul multi-line in liste pentru `Ingredients` si `Steps`.

Proprietati recomandate:

```csharp
public class RecipeFormViewModel
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string SourceUrl { get; set; } = "";
    public string IngredientsText { get; set; } = "";
    public string StepsText { get; set; } = "";
    public string Notes { get; set; } = "";
    public RecipeStatus Status { get; set; } = RecipeStatus.Saved;
    public DateTime SavedAt { get; set; } = DateTime.Now;
    public int? UserId { get; set; }
}
```

Adauga metode/helper-e mici pentru conversie:

- `FromRecipe(Recipe recipe)`
- `ToRecipe()`
- split pe linii pentru ingrediente si pasi;
- elimina liniile goale.
