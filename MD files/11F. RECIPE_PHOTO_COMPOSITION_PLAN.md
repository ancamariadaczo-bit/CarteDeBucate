# Plan 3F - Compunerea infrastructurii foto si verificarea finala

## Scop

Conecteaza prin `AppServiceFactory` componentele implementate si testate separat in planurile 3A-3E.

Acest plan nu introduce reguli noi de business. El rezolva configurarea, construieste obiectele si verifica pregatirea pentru backup ZIP viitor.

## Dependinte

- planurile 3A, 3B, 3C, 3D si 3E finalizate;
- factory-ul database al repository-ului foto din planul 2.

## In afara scopului

- inregistrare in `CarteDeBucate.Web/Program.cs`;
- modificarea pornirii App;
- pornirea automata a reconcilerului;
- fallback JSON pentru fotografii;
- ZIP, `System.IO.Compression` sau `RestorePhotoAsync`;
- schimbari de comportament in storage sau serviciu.

## Regula de lucru

Executa un singur pas, explica fiecare modificare de comportament, nu rula build sau teste, indica verificarea utilizatorului si asteapta aprobarea explicita.

## Regula aprobata pentru path

`AppServiceFactory` este singurul responsabil pentru transformarea configurarii intr-un path foto absolut.

Reguli:

- `DatabasePath` este normalizat la un path absolut;
- directorul DB este baza pentru o valoare `RecipePhotosPath` relativa;
- o valoare `RecipePhotosPath` absoluta este normalizata si folosita direct;
- rezultatul transmis storage-ului este absolut;
- `FileSystemRecipePhotoStorage` nu cunoaste `AppSettings` sau `DatabasePath`;
- storage-ul, nu factory-ul, creeaza directoarele;
- nicio valoare nu este tratata ca path relativ fata de `wwwroot`.

Exemplu:

```text
DatabasePath:      /data/carte/recipes.db
RecipePhotosPath:  recipe-photos
Rezultat:          /data/carte/recipe-photos
```

## Pasul 1 - Adauga rezolvarea path-ului si factory-ul storage-ului

- `CarteDeBucate.Tests/Configuration/AppServiceFactoryTests.cs`.

Adauga o cale explicita pentru database care:

1. normalizeaza `DatabasePath`;
2. determina directorul DB;
3. rezolva `RecipePhotosPath` conform regulilor aprobate;
4. construieste `FileSystemRecipePhotoStorage` cu radacina absoluta.

Adauga teste pentru:

- DB path absolut si photo path relativ;
- DB path relativ si photo path relativ;
- photo path absolut;
- normalizarea segmentelor;
- transmiterea unei radacini absolute;
- lipsa crearii directorului de catre resolver, daca storage-ul nu este construit.

Verificare pentru utilizator: ruleaza numai testele factory-ului pentru path si storage.

Opreste-te si asteapta aprobarea.

## Pasul 2 - Adauga factory-ul RecipePhotoService

- repository-ul foto;
- storage-ul;
- validatorul;
- normalizatorul;
- optiunile;
- `RecipePhotoService`;
- timpul si logger-ele necesare.

Nu adauga fallback JSON. Daca storage mode nu este database, consumatorul nu trebuie sa primeasca un serviciu foto functional prin aceasta cale.

Adauga teste care verifica tipurile construite si transmiterea dependentelor configurabile, fara a testa din nou comportamentul intern al serviciului.

Verificare pentru utilizator: ruleaza numai testele factory-ului pentru serviciul foto.

Opreste-te si asteapta aprobarea.

## Pasul 5 - Verifica pregatirea pentru backup ZIP

Adauga numai teste sau documentatie de contract care confirma ca serviciul poate:

- enumera metadata publica a fotografiilor unei retete;
- deschide continutul fiecarei fotografii ca stream;
- pastra metadata portabila aprobata;
- evita expunerea sau reutilizarea `StorageFileName`.

Un backup viitor va pastra:

- `OriginalFileName` normalizat;
- `CreatedAtUtc`;
- `DisplayOrder`;
- `Origin`;
- continutul fotografiei.

La restaurare se vor regenera sau recalcula:

- `Id`;
- `RecipeId`, prin maparea la reteta importata;
- `StorageFileName`;
- `ContentType`, din continut;
- `FileSize`, din bytes reali.

Nu implementa restaurarea, arhiva sau modificari in `IRecipeBackupService`.

Verificare pentru utilizator: ruleaza numai testele de contract pentru pregatirea ZIP.

Opreste-te si asteapta aprobarea.

## Pasul 6 - Verificarea finala a roadmap-ului foto Core

Agentul nu ruleaza teste si nu ruleaza build.

Cere utilizatorului sa ruleze:

```bash
dotnet test CarteDeBucate.Tests/CarteDeBucate.Tests.csproj --filter RecipePhoto
dotnet test CarteDeBucate.Tests/CarteDeBucate.Tests.csproj --filter RecipeLibraryServiceTests
dotnet test CarteDeBucate.Tests/CarteDeBucate.Tests.csproj
```

Confirma explicit:

- uploadul functioneaza pentru stream seekable si non-seekable;
- bytes reali si limita de 10 MiB sunt aplicate;
- limita simpla de 20 functioneaza in fluxul normal;
- limitarea pentru uploaduri concurente este documentata;
- JPEG, PNG si WebP sunt detectate din continut;
- numele original este normalizat;
- numele final este generat intern;
- path-ul foto este rezolvat de factory;
- storage-ul primeste o radacina absoluta in afara `wwwroot`;
- path traversal este respins;
- staging-ul, carantina si compensarea functioneaza;
- fisierul lipsa nu blocheaza stergerea metadata sau a retetei;
- reconcilerul respecta pragul si nu sterge orfanii finali;
- accesul este filtrat pe utilizator;
- modul JSON ramane fara suport foto;
- `StorageFileName`, tokenurile si path-urile nu sunt expuse;
- Web, App si backup-ul nu au fost modificate.

Opreste-te, asteapta rezultatele utilizatorului si cere aprobarea finala.

## Definitia de finalizare

Planul 3F este finalizat cand toate componentele Core pot fi construite prin factory-uri, contractul pentru ZIP viitor este verificat, utilizatorul confirma comenzile finale si agentul nu a rulat personal teste sau build-uri.
