# Plan 1 - Versionarea importului si exportului de backup pentru retete

## Scop

Pregateste formatul de backup pentru evolutii viitoare, astfel incat aplicatia sa poata:

- exporta un document JSON cu versiune explicita;
- importa noul document JSON versionat;
- importa in continuare versiunea 1 existenta, care are la radacina direct un `List<Recipe>`;
- adauga ulterior un container ZIP cu acelasi document JSON si cu fotografii, fara sa schimbam din nou structura logica a backup-ului.

Acest plan nu implementeaza ZIP si nu include fotografii. El stabileste doar contractul versionat peste care acestea vor fi adaugate ulterior.

## Contract tinta

Formatul JSON nou trebuie sa fie un document de backup, nu o lista neincadrata. Forma initiala propusa este:

```json
{
  "version": 2,
  "exportedAtUtc": "2026-09-02T12:00:00.0000000Z",
  "recipes": []
}
```

Decizii:

- `version` este un numar intreg si reprezinta versiunea schemei logice;
- `exportedAtUtc` este metadada informativa, in UTC;
- `recipes` contine DTO-uri de backup;
- JSON-ul existent, cu un array de retete direct la radacina, este versiunea 1 implicita;
- versiunea 1 nu are proprietate `version`, deoarece forma radacinii o identifica;
- noul document cu `version`, `exportedAtUtc` si `recipes` este versiunea 2;
- noul document nu contine proprietatea `format`;
- exportul produce numai versiunea 2;
- importul accepta versiunea 1 si versiunea 2;
- noul export JSON nu contine deloc proprietatile `Id` si `UserId`, nici macar cu valoarea `null`;
- `Id` si `UserId` pot exista in versiunea 1 pentru compatibilitate, dar valorile lor sunt ignorate la import;
- la import, baza de date genereaza noul `Id`, iar serviciul atribuie `UserId` din contextul curent;
- `SourceUrl` ramane obligatoriu si ramane cheia folosita de comportamentul actual pentru detectarea duplicatelor;
- un ZIP viitor va contine acest document ca manifest JSON si fisierele foto separat;
- versiunea 2 se citeste din proprietatea `version`, iar versiunea 1 se identifica prin radacina de tip array;
- versiunea nu se deduce din extensia fisierului;
- nu se introduce acum nicio proprietate alternativa care sa inlocuiasca `format`.

## Pasul 6 - Detecteaza forma JSON fara a importa nimic

Fisier nou propus:

- `CarteDeBucate.Core/Services/Backup/RecipeBackupDocumentReader.cs`.

Responsabilitate unica:

- inspecteaza radacina JSON;
- recunoaste versiunea 2 cand radacina este obiect si proprietatea `version` are valoarea `2`;

- radacina este obiect;
- proprietatea `version` exista si este `2`;
- `exportedAtUtc` exista si poate fi citit;
- `recipes` exista si poate fi deserializat.

Modifica `ImportFromJsonContent` sa foloseasca reader-ul si mapper-ul, apoi sa reutilizeze aceleasi reguli existente de duplicate, `Id` si `UserId`.

- versiunea `1` scrisa intr-un obiect, deoarece versiunea 1 valida este numai forma array;
- versiune zero sau negativa;
- `exportedAtUtc` lipsa sau invalid;
- `recipes` lipsa ori `null`.

Nu adauga fallback silentios pentru un obiect necunoscut.
