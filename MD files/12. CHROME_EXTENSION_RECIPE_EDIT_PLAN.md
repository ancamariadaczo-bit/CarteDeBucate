# Plan 12 - Editarea retetei extrase in extensia Chrome

## Scop

Adauga in `CarteDeBucate.ChromeExtension` posibilitatea de a edita o reteta dupa extragere si inainte de `Print / Save PDF`.

Fluxul tinta este:

1. utilizatorul apasa `Extract Recipe`;
2. popup-ul afiseaza reteta si butoanele `Edit Recipe` si `Print / Save PDF`;
3. `Edit Recipe` deschide o fereastra separata de editare;
4. utilizatorul poate modifica numele, URL-ul sursei, URL-ul imaginii, ingredientele si instructiunile;
5. `Print / Save PDF` din editor trimite versiunea editata catre pagina de printare existenta;
6. `print.html` continua sa afiseze reteta si sa deschida dialogul browserului pentru printare sau salvare PDF.

Editarea este temporara si se aplica numai versiunii trimise la printare. Planul nu salveaza reteta in aplicatia CarteDeBucate, intr-o baza de date, intr-un fisier JSON sau pe site-ul sursa.

## Regula obligatorie de lucru pentru agent

Executa exact un singur pas mic si apoi opreste-te complet.

Dupa fiecare pas:

1. arata fisierele modificate si rezumatul schimbarii;
2. nu rula teste, build sau extensia Chrome;
3. spune utilizatorului ce verificare manuala trebuie sa faca, daca pasul poate fi verificat separat;
4. asteapta rezultatul si aprobarea explicita a utilizatorului;
5. nu continua fara comanda explicita a utilizatorului.

Nu combina pasi si nu face commit sau push fara o cerere explicita a utilizatorului.

Daca implementarea necesita schimbarea unui contract stabilit in acest plan, opreste-te si cere decizia utilizatorului.

## Starea actuala

- `popup.js` pastreaza reteta extrasa in variabila `currentRecipe`.
- Dupa o extragere reusita, popup-ul afiseaza reteta si butonul `Print / Save PDF`.
- Butonul de printare serializeaza `currentRecipe` in `localStorage`, sub cheia `recipeToPrint`.
- Popup-ul deschide `print.html` intr-o fereastra Chrome de `900x700`.
- `print.js` citeste `recipeToPrint`, construieste pagina si deschide automat dialogul de printare.
- Obiectul extras contine in prezent `name`, `sourceUrl`, `author`, `imageUrl`, `ingredients` si `steps`.
- Toate textele vizibile ale extensiei sunt in limba engleza.
- Popup-ul are latimea fixa de `420px`; aceasta latime nu trebuie schimbata.

## Decizii de design obligatorii

### Editor separat

- Adauga `edit.html`, `edit.css` si `edit.js` in `CarteDeBucate.ChromeExtension`.
- Nu transforma popup-ul de `420px` intr-un formular mare.
- `Edit Recipe` deschide editorul intr-o fereastra Chrome de `900x700`, la fel ca pagina de printare.
- Nu adauga biblioteci externe sau framework-uri.

### Transferul retetei

- Refoloseste cheia existenta `recipeToPrint`; nu introduce o a doua cheie pentru acelasi payload.
- La apasarea `Edit Recipe`, popup-ul scrie `currentRecipe` in `recipeToPrint`, apoi deschide `edit.html`.
- `edit.js` citeste payload-ul din `recipeToPrint` si pastreaza obiectul original in memorie.
- La confirmarea editarii, editorul suprascrie `recipeToPrint` cu versiunea editata si navigheaza aceeasi fereastra la `print.html`.
- Nu deschide o a doua fereastra din editor.
- Fluxul direct `Print / Save PDF` din popup trebuie sa ramana functional si neschimbat semantic.

### Campurile editabile

Editorul expune:

- `Recipe name` - camp text obligatoriu;
- `Source URL` - camp URL obligatoriu;
- `Image URL` - camp URL optional;
- `Ingredients` - randuri editabile, in ordinea existenta;
- `Instructions` - randuri editabile, in ordinea existenta.

`author` nu este editat in aceasta versiune, dar trebuie pastrat nemodificat in obiectul final.

Pentru ingrediente si instructiuni:

- fiecare element are propriul camp;
- instructiunile folosesc `textarea`, pentru a permite texte mai lungi;
- exista `Add Ingredient` si `Add Instruction`;
- fiecare rand are `Remove`;
- elementele noi se adauga la sfarsit;
- reordonarea prin drag-and-drop sau butoane sus/jos nu face parte din acest plan;
- ordinea elementelor din DOM devine ordinea din obiectul final.

### Validare si normalizare

La trimiterea formularului:

- elimina spatiile de la inceputul si sfarsitul valorilor;
- `name` trebuie sa ramana ne-gol;
- elimina ingredientele si instructiunile care au devenit goale;
- trebuie sa ramana cel putin un ingredient si o instructiune;
- `Source URL` trebuie sa ramana ne-gol;
- transforma `Image URL` gol in `null`;
- pentru `Source URL` si pentru un `Image URL` ne-gol, reproduce in JavaScript comportamentul `UrlValidator.IsValidHttpUrl()` din Core:
  - URL-ul trebuie sa fie absolut;
  - accepta numai schemele `http` si `https`;
  - URL-ul trebuie sa contina un host ne-gol;
- valideaza URL-ul dupa eliminarea spatiilor de la inceput si sfarsit, dar pastreaza in obiect valoarea editata doar cu aceasta normalizare prin `trim()`;
- pastreaza proprietatile obiectului original care nu sunt editate;
- nu foloseste `innerHTML` pentru continut provenit din reteta;
- afiseaza erorile in pagina editorului si nu navigheaza la `print.html` pana cand formularul este valid.

Validarea echivalenta cu `UrlValidator` este numai sintactica. Nu face cereri de retea pentru a verifica existenta paginii sau accesibilitatea imaginii. Browserul si fluxul existent de printare gestioneaza imaginea inaccesibila.

### Texte UI

Toate textele noi sunt in engleza. Foloseste exact etichetele principale:

- `Edit Recipe`;
- `Recipe name`;
- `Source URL`;
- `Image URL`;
- `Ingredients`;
- `Instructions`;
- `Add Ingredient`;
- `Add Instruction`;
- `Remove`;
- `Print / Save PDF`;
- `Cancel`.

Pentru payload absent sau invalid foloseste mesajul `No recipe was found to edit.`

## Limite obligatorii

- Modifica numai `CarteDeBucate.ChromeExtension`.
- Nu modifica extractoarele `jsonLdImporter.js`, `htmlImporter.js` sau `recipeExtractor.js`.
- Nu rezolva in acest plan problema site-urilor care grupeaza mai multe instructiuni intr-un singur pas.
- Nu modifica `print.html`, `print.css` sau `print.js`, exceptand cazul in care utilizatorul aproba explicit o problema de compatibilitate descoperita in timpul implementarii.
- Nu modifica numele extensiei, descrierea, iconitele sau permisiunile din `manifest.json`.
- Nu modifica latimea de `420px` a popup-ului.
- Nu adauga persistenta permanenta, autosave, istoric, undo/redo sau sincronizare cu aplicatia CarteDeBucate.
- Nu adauga suport de localizare; textele raman direct in engleza in aceasta versiune.
- Nu interpreta continutul editat ca HTML.

## Structura tinta

Fisiere modificate:

- `CarteDeBucate.ChromeExtension/popup.html`;
- `CarteDeBucate.ChromeExtension/popup.js`.

Fisierul `popup.css` se modifica numai daca cele doua butoane vizibile dupa extragere nu se incadreaza corect in stilul existent. Latimea popup-ului ramane neschimbata.

Fisiere noi:

- `CarteDeBucate.ChromeExtension/edit.html`;
- `CarteDeBucate.ChromeExtension/edit.css`;
- `CarteDeBucate.ChromeExtension/edit.js`.

Fisiere care trebuie sa ramana nemodificate:

- `CarteDeBucate.ChromeExtension/manifest.json`;
- `CarteDeBucate.ChromeExtension/print.html`;
- `CarteDeBucate.ChromeExtension/print.css`;
- `CarteDeBucate.ChromeExtension/print.js`;
- toate fisierele din `CarteDeBucate.ChromeExtension/extractors`.

## Pasul 1 - Adauga structura statica a editorului

Creeaza `CarteDeBucate.ChromeExtension/edit.html`.

Include:

- `lang="en"` si `charset="UTF-8"`;
- titlul `Edit Recipe`;
- referinte locale catre `edit.css` si `edit.js`;
- antet cu iconita existenta `icons/icon48.png` si numele extensiei;
- un container pentru mesajele de eroare;
- formularul cu sectiunile pentru campurile simple, ingrediente si instructiuni;
- butoanele `Print / Save PDF` si `Cancel`;
- containere goale pentru randurile dinamice de ingrediente si instructiuni.

Nu implementa JavaScript si nu modifica popup-ul in acest pas.

Opreste-te si asteapta aprobarea utilizatorului.

## Pasul 2 - Adauga stilurile editorului

Creeaza `CarteDeBucate.ChromeExtension/edit.css`.

Cerinte:

- formular lizibil intr-o fereastra de `900x700`;
- continut centrat cu o latime maxima rezonabila;
- label-urile sunt asociate vizual clar cu inputurile;
- inputurile si `textarea` ocupa latimea disponibila;
- randurile dinamice au campul principal si butonul `Remove` alaturat;
- controalele raman utilizabile la o latime mai mica;
- mesajele de eroare sunt vizibile fara a folosi numai culoarea ca semnal;
- nu copia stilurile de printare si nu adauga reguli `@media print`.

Nu modifica JavaScript in acest pas.

Opreste-te si cere utilizatorului sa inspecteze stilurile din fisier.

## Pasul 3 - Adauga butonul Edit Recipe in popup

Modifica `CarteDeBucate.ChromeExtension/popup.html`.

Adauga `Edit Recipe` in containerul `.controls`:

- butonul este ascuns initial cu `hidden`;
- este plasat inainte de `Print / Save PDF`;
- foloseste un id explicit, de exemplu `editButton`.

Nu adauga inca handler-ul de click.

Opreste-te si asteapta aprobarea utilizatorului.

## Pasul 4 - Controleaza vizibilitatea butonului Edit Recipe

Modifica `CarteDeBucate.ChromeExtension/popup.js`.

- obtine referinta la `editButton`;
- dupa o extragere reusita, afiseaza `Edit Recipe` impreuna cu `Print / Save PDF`;
- dupa o extragere esuata, ascunde ambele butoane;
- nu modifica inca transferul prin `localStorage` si nu deschide editorul.

Opreste-te si cere utilizatorului sa reincarce extensia si sa verifice manual cele doua stari ale popup-ului.

## Pasul 5 - Deschide editorul din popup

Modifica `CarteDeBucate.ChromeExtension/popup.js`.

La click pe `Edit Recipe`:

1. daca `currentRecipe` este `null`, nu face nimic;
2. serializeaza `currentRecipe` in cheia `recipeToPrint`;
3. deschide `edit.html` cu `chrome.windows.create`;
4. foloseste `type: "popup"`, `width: 900` si `height: 700`.

Nu modifica handler-ul existent pentru printarea directa.

Opreste-te si cere utilizatorului sa verifice ca editorul se deschide numai dupa extragerea unei retete.

## Pasul 6 - Citeste si valideaza payload-ul editorului

Creeaza inceputul implementarii in `CarteDeBucate.ChromeExtension/edit.js`.

- citeste `recipeToPrint` din `localStorage`;
- trateaza separat cheia absenta si JSON-ul invalid;
- verifica minimal ca rezultatul este un obiect;
- pentru payload invalid, afiseaza `No recipe was found to edit.` si dezactiveaza formularul si actiunea de printare;
- pastreaza obiectul original pentru a conserva proprietatile needitabile.

Nu popula inca randurile dinamice.

Opreste-te si cere utilizatorului sa verifice manual editorul cu payload valid si fara payload.

## Pasul 7 - Populeaza campurile simple

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

Populeaza in siguranta, prin proprietatea `value`:

- `Recipe name` din `recipe.name`;
- `Source URL` din `recipe.sourceUrl` sau sir gol;
- `Image URL` din `recipe.imageUrl` sau sir gol.

Nu folosi `innerHTML`.

Opreste-te si cere utilizatorului sa compare valorile cu preview-ul din popup.

## Pasul 8 - Afiseaza ingredientele editabile

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

- creeaza cate un rand pentru fiecare valoare din `recipe.ingredients`;
- fiecare rand contine un camp text si un buton `Remove`;
- foloseste o functie mica reutilizabila pentru crearea randului;
- valorile sunt atribuite prin `value`;
- pastreaza ordinea initiala;
- nu implementa inca adaugarea sau stergerea efectiva.

Opreste-te si cere utilizatorului sa verifice numarul, ordinea si textele ingredientelor.

## Pasul 9 - Afiseaza instructiunile editabile

- creeaza cate un rand pentru fiecare valoare din `recipe.steps`;
- fiecare rand contine un `textarea` si un buton `Remove`;
- foloseste o functie separata de cea pentru ingrediente atunci cand structura campului difera;
- pastreaza ordinea initiala;
- nu incerca sa desparti automat un pas care contine mai multe instructiuni numerotate.

Opreste-te si cere utilizatorului sa verifice numarul, ordinea si textele instructiunilor.

- conecteaza `Add Ingredient`;
- conecteaza fiecare buton `Remove` din sectiunea ingredientelor;
- randul nou se adauga la sfarsit si primeste focus;
- permite temporar eliminarea tuturor randurilor; validarea finala va bloca printarea.

Opreste-te si cere utilizatorului sa verifice manual adaugarea, editarea si eliminarea.

## Pasul 11 - Implementeaza adaugarea si eliminarea instructiunilor

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

- conecteaza `Add Instruction`;
- conecteaza fiecare buton `Remove` din sectiunea instructiunilor;
- randul nou se adauga la sfarsit si primeste focus;
- nu adauga reordonare in acest pas.

Opreste-te si cere utilizatorului sa verifice manual adaugarea, editarea si eliminarea.

## Pasul 12 - Colecteaza si valideaza formularul

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

La submit:

1. previne submit-ul HTML implicit;
2. citeste si normalizeaza campurile conform regulilor aprobate;
3. colecteaza ingredientele si instructiunile in ordinea DOM;
4. elimina elementele goale;
5. valideaza numele, `Source URL`, cel putin un ingredient si cel putin o instructiune;
6. pentru `Source URL` si pentru un `Image URL` ne-gol, verifica in JavaScript ca URL-ul este absolut, foloseste `http` sau `https` si are host, echivalent cu `UrlValidator.IsValidHttpUrl()`;
7. afiseaza erori specifice pentru `Source URL` si `Image URL` si opreste fluxul daca datele nu sunt valide;
8. construieste un obiect nou pornind de la obiectul original si suprascrie numai campurile editabile.

Nu naviga inca la `print.html`.

Opreste-te si cere utilizatorului sa verifice cazurile valide si invalide.

## Pasul 13 - Trimite versiunea editata la printare

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

Dupa validare reusita:

1. serializeaza obiectul editat in `localStorage` sub cheia `recipeToPrint`;
2. navigheaza fereastra curenta la `print.html`;
3. lasa `print.js` sa execute fluxul existent de `Print / Save PDF`.

Nu duplica logica de construire a paginii de printare in editor.

Opreste-te si cere utilizatorului sa verifice ca PDF-ul contine valorile editate.

## Pasul 14 - Implementeaza Cancel si trateaza erorile locale

Modifica `CarteDeBucate.ChromeExtension/edit.js`.

- `Cancel` inchide fereastra editorului prin `window.close()`;
- erorile de citire, serializare sau initializare sunt afisate in editor;
- nu sterge payload-ul original daca editarea este anulata;
- nu adauga confirmare pentru modificari nesalvate in aceasta versiune.

Opreste-te si cere utilizatorului sa verifice anularea si un payload JSON invalid.

## Pasul 15 - Verificarea manuala finala

Agentul nu ruleaza aceasta verificare. Cere utilizatorului sa:

1. deschida `chrome://extensions`;
2. reincarce extensia unpacked;
3. extraga o reteta cu imagine;
4. confirme ca apar `Edit Recipe` si `Print / Save PDF`;
5. confirme ca printarea directa produce aceeasi reteta ca inainte;
6. extraga din nou reteta si deschida editorul;
7. modifice numele, sursa si imaginea;
8. editeze, adauge si elimine ingrediente;
9. editeze, adauge si elimine instructiuni;
10. apese `Print / Save PDF` si confirme ca pagina de printare foloseste toate valorile editate;
11. verifice ca `Cancel` inchide editorul fara a deschide printarea;
12. verifice mesajele pentru nume gol, zero ingrediente si zero instructiuni;
13. verifice faptul ca URL-urile absolute `http` si `https` sunt acceptate;
14. verifice faptul ca URL-urile relative, URL-urile fara protocol si schemele diferite de `http` sau `https` sunt respinse;
15. verifice faptul ca un `Source URL` gol este respins, iar un `Image URL` gol este acceptat si devine `null`;
16. verifice editorul pentru o reteta fara imagine;
17. confirme ca popup-ul a ramas la latimea de `420px`;
18. confirme ca toate textele noi sunt in engleza.

Daca utilizatorul raporteaza o problema, agentul trebuie sa corecteze numai pasul relevant si sa astepte din nou verificarea.

## Criterii finale de acceptare

- `Edit Recipe` este disponibil numai dupa o extragere reusita.
- Editorul se deschide separat si nu mareste popup-ul extensiei.
- Toate campurile aprobate pot fi modificate.
- Ingredientele si instructiunile pot fi adaugate si eliminate.
- Proprietatile needitate, inclusiv `author`, sunt pastrate.
- `Source URL` este obligatoriu si respecta acelasi contract sintactic ca `UrlValidator.IsValidHttpUrl()` din Core.
- `Image URL` poate fi `null`; cand este ne-gol, respecta acelasi contract sintactic ca `UrlValidator.IsValidHttpUrl()` din Core.
- Datele invalide nu ajung la pagina de printare.
- Pagina de printare primeste si afiseaza versiunea editata.
- Printarea directa din popup continua sa functioneze.
- Nu sunt adaugate permisiuni Chrome noi.
- Nu este modificata logica extractoarelor sau a paginii de printare.
- Nu este adaugata persistenta permanenta.
- Toate textele noi sunt in engleza.
