# Plan pentru eliminarea incarcarilor complete de RecipeSummary

## Scop

Acest plan trateaza cele patru utilizari ramase ale metodei:

```csharp
List<RecipeSummary> GetRecipeSummaries()
```

si descrie eliminarea separata a metodei vechi:

```csharp
List<RecipeSummary> SearchRecipes(string searchText)
```

Modificarile trebuie facute cate un pas pe rand. Dupa fiecare pas se opreste
implementarea pentru verificare.

## Reguli

- Nu se sterge `GetRecipeSummaries()` inainte ca toate cele patru utilizari sa fie migrate.
- Selectoarele pentru View/Edit/Delete trebuie sa ramana functionale.
- Selectoarele Classic si Rich trebuie paginate, nu inlocuite cu search obligatoriu.
- Metodele UI `ClassicConsoleRecipeApp.SearchRecipes()` si
  `RichConsoleRecipeApp.SearchRecipe()` nu se sterg.
- Se elimina doar vechiul API nepaginat `SearchRecipes(...)` din service si repository.
- Nu se ruleaza automat build sau teste. Acestea raman verificari manuale.

## Situatia actuala

### Cazul 1: verificarea din `RecipeLibraryService.DeleteRecipe`

Fisier:

- `CarteDeBucate.Core/Services/Library/RecipeLibraryService.cs`

Codul actual incarca toate sumarizarile si cauta un singur ID:

```csharp
RecipeSummary? recipe = GetRecipeSummaries()
    .FirstOrDefault(recipe => recipe.Id == recipeId);
```

Aceasta incarcare nu este necesara. Repository-ul trebuie sa execute stergerea
filtrata si sa returneze daca reteta a fost gasita si stearsa.

### Cazul 2: reincarcarea din Rich Console inainte de confirmarea stergerii

Fisier:

- `CarteDeBucate.App/ConsoleUI/RichConsole/RichConsoleRecipeApp.cs`

`SelectExistingRecipe(...)` returneaza deja un `RecipeSummary`. Fluxul de delete
incarca apoi din nou toate sumarizarile pentru acelasi ID. A doua incarcare este
redundanta.

### Cazul 3: selectorul View/Edit/Delete din Rich Console

Fisier:

- `CarteDeBucate.App/ConsoleUI/RichConsole/RichConsoleRecipeApp.cs`

Selectorul primeste acum toate retetele. El trebuie sa ceara cate o pagina prin
`GetRecipeSummariesPage(...)` si sa permita:

- selectarea unei retete din pagina curenta;
- pagina urmatoare;
- pagina anterioara;
- revenirea la meniul principal.

### Cazul 4: lista View/Edit/Delete din Classic Console

Fisier:

- `CarteDeBucate.App/ConsoleUI/ClassicConsole/ClassicConsoleRecipeApp.cs`

Classic afiseaza toate sumarizarile, apoi cere ID-ul. Fluxul trebuie sa afiseze
cate o pagina si sa accepte in acelasi selector:

- un ID din pagina curenta;
- `n` pentru pagina urmatoare;
- `p` pentru pagina anterioara;
- `0` pentru meniul principal.

## Etapa 1: elimina reincarcarea redundanta din Rich Delete

Fisier:

## Etapa 2: corecteaza stergerea din service

### Decizie de contract

Metodele repository de delete trebuie sa returneze `bool`:

```csharp
bool DeleteRecipe(int recipeId);
bool DeleteRecipeForUser(int recipeId, int userId);
```

Rezultat:

- `true`: reteta a fost gasita in contextul permis si stearsa;
- `false`: ID-ul nu exista sau reteta nu apartine utilizatorului.

Aceasta varianta evita un query separat de existenta si evita incarcarea unei
retete complete sau a tuturor sumarizarilor.

### Pasul 2.1: schimba rezultatul delete in repository-ul JSON

Fisier:

- `CarteDeBucate.Core/Data/Repositories/JsonRecipeRepository.cs`

Modificari:

- `DeleteRecipe(...)` returneaza `false` cand ID-ul nu exista;
- returneaza `true` dupa eliminare si salvare;
- `DeleteRecipeForUser(...)` returneaza `false` daca ID-ul nu apartine userului;
- returneaza `true` dupa eliminare si salvare.

Nu modifica inca service-ul.

### Pasul 2.2: schimba rezultatul delete in repository-ul SQLite

Fisier:

- `CarteDeBucate.Core/Data/Repositories/DatabaseRecipeRepository.cs`

Modificari:

- `DeleteRecipe(...)` returneaza daca randul principal a fost sters;
- `DeleteRecipeForUser(...)` returneaza `false` daca reteta nu apartine userului;
- returneaza `true` numai dupa commit;
- rollback-ul si exceptiile existente raman neschimbate.

Metoda care sterge randul principal poate returna numarul de randuri afectate
sau un `bool`.

### Pasul 2.3: actualizeaza contractul repository

Fisier:

- `CarteDeBucate.Core/Data/Repositories/IRecipeRepository.cs`

Modificare:

- schimba cele doua metode `void Delete...` in `bool Delete...`.

In acelasi pas se actualizeaza:

- `CarteDeBucate.Tests/Fakes/FakeRecipeRepository.cs`;
- valorile de tracking necesare testelor.

### Pasul 2.4: foloseste rezultatul stergerii in service

Fisier:

- `CarteDeBucate.Core/Services/Library/RecipeLibraryService.cs`

Modificari:

- pastreaza validarea `recipeId <= 0`;
- elimina `GetRecipeSummaries().FirstOrDefault(...)`;
- apeleaza metoda delete potrivita contextului curent;
- returneaza `RecipeNotFound` cand repository-ul returneaza `false`;
- returneaza `RecipeDeleted` cand repository-ul returneaza `true`.

### Pasul 2.5: actualizeaza testele de delete

Fisiere:

- `CarteDeBucate.Tests/Services/RecipeLibraryServiceTests.cs`;
- `CarteDeBucate.Tests/Data/JsonRecipeRepositoryTests.cs`;
- `CarteDeBucate.Tests/DatabaseRecipeRepositoryTests.cs`.

Scenarii:

- ID invalid nu apeleaza repository-ul;
- reteta inexistenta returneaza esec;
- reteta globala existenta este stearsa;
- reteta userului curent este stearsa;
- reteta altui user nu este stearsa;
- service-ul nu mai apeleaza `GetRecipeSummaries()`.

## Etapa 3: pagineaza selectorul Rich Console

### Pasul 3.1: defineste rezultatul generic al unei selectii paginate

Zona:

- `CarteDeBucate.App/ConsoleUI/`

Adauga un singur tip generic mic, reutilizabil de ambele console:

```csharp
SelectionResult<T>
```

Tipul poate reprezenta exact una dintre actiuni:

- valoare selectata (`T`);
- pagina urmatoare;
- pagina anterioara;
- revenire la meniu;
- input invalid.

In Rich Console, tipul va fi folosit ca:

```csharp
SelectionResult<RecipeSummary>
```

In Classic Console, tipul va fi folosit ca:

```csharp
SelectionResult<int>
```

Nu adauga tipuri separate pentru Rich si Classic, cum ar fi
`RecipeSelectionResult` sau `RecipeIdSelectionResult`.

Nu modifica inca fluxurile View/Edit/Delete.

### Pasul 3.2: extinde contractul reader-ului Rich

Fisiere:

- `CarteDeBucate.App/ConsoleUI/RichConsole/IRichConsoleReader.cs`;
- `CarteDeBucate.App/ConsoleUI/RichConsole/RichConsoleReader.cs`.

Modificari:

- selectorul primeste retetele paginii curente;
- primeste `HasPreviousPage` si `HasNextPage`;
- adauga numai actiunile de navigare disponibile;
- pastreaza optiunea de revenire la meniul principal;
- returneaza `SelectionResult<RecipeSummary>`.

### Pasul 3.3: adapteaza fake reader-ul Rich

Fisier:

- `CarteDeBucate.Tests/Fakes/FakeRichConsoleReader.cs`

Modificari:

- permite o coada de rezultate de selectie;
- inregistreaza paginile de retete primite;
- pastreaza suportul pentru selectarea unei retete.

### Pasul 3.4: pagineaza `SelectExistingRecipe`

Fisier:

- `CarteDeBucate.App/ConsoleUI/RichConsole/RichConsoleRecipeApp.cs`

Comportament:

- porneste de la pagina 1;
- cere `_recipeLibraryService.GetRecipeSummariesPage(pageNumber, PageSize)`;
- trimite doar `Items` catre reader;
- la Next/Previous cere pagina noua;
- la limita ramane pe pagina curenta;
- la Back returneaza la meniul principal;
- la selectie returneaza `RecipeSummary`;
- daca totalul este zero, afiseaza mesajul existent.

### Pasul 3.5: actualizeaza testele Rich

Fisier:

- `CarteDeBucate.Tests/RichConsoleRecipeAppTests.cs`

Scenarii:

- View selecteaza o reteta din prima pagina;
- Edit navigheaza la pagina urmatoare si selecteaza;
- Delete navigheaza inapoi si selecteaza;
- Next pe ultima pagina ramane pe ultima pagina;
- Previous pe prima pagina ramane pe prima pagina;
- Back revine la meniu;
- lista goala afiseaza mesajul existent.


Scenarii:

- View/Edit/Delete functioneaza de pe prima pagina;
