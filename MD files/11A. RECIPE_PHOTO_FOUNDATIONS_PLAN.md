# Plan 3A - Fundatiile serviciului foto

## Scop

Defineste vocabularul, configurarea si regulile pure ale functionalitatii foto.

La finalul acestui plan exista:

- configurarea pentru directorul fotografiilor;
- optiunile si formatele acceptate;
- codurile si modelele publice de rezultat;
- validarea continutului;
- normalizarea numelui original;
- contractul public `IRecipePhotoService`.

Acest plan nu salveaza fisiere, nu acceseaza SQLite prin serviciul foto si nu implementeaza `RecipePhotoService`.

## Dependinte

- planul 2 pentru `RecipePhotoOrigin`;
- regulile comune din `MD files/11. RECIPE_PHOTO_SERVICE_PLAN.md`.

## In afara scopului

- `IRecipePhotoStorage` si `FileSystemRecipePhotoStorage`;
- staging, fisiere finale si carantina;
- apeluri catre repository;
- implementarea `RecipePhotoService`;
- factory-uri;
- Web, App si ZIP.

## Regula de lucru

Executa un singur pas, explica fiecare modificare de comportament, nu rula build sau teste, indica verificarea utilizatorului si asteapta aprobarea explicita.

## Contractele tinta

### Configurare

`AppSettings.RecipePhotosPath`:

- are valoarea implicita `recipe-photos`;
- accepta o valoare nevida din `appsettings.json`;
- ignora valorile goale sau formate numai din spatii;
- nu creeaza directoare;
- ramane o valoare configurata, nu un path absolut garantat.

Rezolvarea fata de `DatabasePath` apartine planului 3F.

### Optiuni

`RecipePhotoOptions` contine:

- `MaxFileSizeBytes = 10 * 1024 * 1024`;
- `MaxPhotosPerRecipe = 20`;
- `ReconciliationMinimumAge = TimeSpan.FromHours(24)`.

Valorile sunt configurabile de dezvoltator sau administrator, dar nu sunt setari UI pentru utilizator.

### Formate

`RecipePhotoFormat`:

- `Unknown = 0`;
- `Jpeg = 1`;
- `Png = 2`;
- `WebP = 3`.

`RecipePhotoFormats` este registrul unic pentru:

- MIME-ul normalizat;
- extensia canonica;
- detectarea semnaturii continutului.

Formatele initiale sunt JPEG, PNG si WebP. Extensia numelui original nu reprezinta dovada formatului.

### Coduri de rezultat

`RecipePhotoResultCode` poate exprima cel putin:

- `Success`;
- `DeletedMetadataFileWasMissing`;
- `CleanupPending`;
- `InvalidRecipeId`;
- `RecipeNotFound`;
- `PhotoNotFound`;
- `PhotoLimitReached`;
- `EmptyContent`;
- `FileTooLarge`;
- `UnsupportedFormat`;
- `InvalidContent`;
- `ContentFileMissing`;
- `StorageFailure`;
- `PersistenceFailure`.

Nu exista `AccessDenied`. Resursele altui utilizator sunt raportate ca inexistente.

### Metadata publica

`RecipePhotoInfo` contine:

- `Id`;
- `RecipeId`;
- `OriginalFileName`;
- `ContentType`;
- `FileSize`;
- `CreatedAtUtc`;
- `DisplayOrder`;
- `Origin`.

Nu contine `StorageFileName`, tokenuri sau path-uri.

### Rezultate publice

- `RecipePhotoResult`: `IsSuccess`, `Code`, `Message`, `Photo`;
- `RecipePhotosResult`: `IsSuccess`, `Code`, `Message`, `Photos`;
- `RecipePhotoContentResult`: `IsSuccess`, `Code`, `Message`, `Content`, `ContentType`, `OriginalFileName`.

Reguli:

- o lista goala este succes daca reteta exista;
- pe esec, `Content` este `null`;
- consumatorul foloseste `Code`, nu textul din `Message`;
- stream-ul returnat pe succes apartine consumatorului.

### Contractul serviciului

```csharp
Task<RecipePhotoResult> AddPhotoAsync(
    int recipeId,
    Stream content,
    string originalFileName,
    string declaredContentType,
    long? declaredLength,
    RecipePhotoOrigin origin,
    CancellationToken cancellationToken = default);

RecipePhotosResult GetPhotosForRecipe(int recipeId);
RecipePhotoContentResult GetPhotoContent(int photoId);
RecipePhotoResult DeletePhoto(int photoId);
```

Contractul nu foloseste `IFormFile` si nu expune tipurile interne ale storage-ului.

## Pasul 5 - Implementeaza validatorul continutului

Fisier nou:

- `CarteDeBucate.Core/Services/Photos/RecipePhotoValidator.cs`.

Validatorul primeste un stream seekable si metadata declarata, apoi:

- respinge continutul gol;
- detecteaza JPEG, PNG sau WebP dupa semnatura;
- compara formatul detectat cu MIME-ul declarat;
- intoarce formatul si MIME-ul normalizat;
- nu foloseste extensia originala drept dovada;
- readuce stream-ul la pozitia initiala;
- nu scrie pe disc;
- nu inchide stream-ul primit.

Adauga teste pentru fiecare format valid, MIME nepotrivit, continut falsificat, semnatura incompleta, format necunoscut si restaurarea pozitiei stream-ului.

Verificare pentru utilizator: ruleaza numai testele validatorului.

Opreste-te si asteapta aprobarea.

## Pasul 6 - Implementeaza normalizarea numelui original

Fisier nou:

- `CarteDeBucate.Core/Services/Photos/RecipePhotoFileNameNormalizer.cs`.

Reguli:

- elimina componentele de director pentru separatorii `/` si `\\`;
- elimina caracterele de control;
- elimina spatiile exterioare;
- limiteaza rezultatul la 255 de caractere;
- inlocuieste extensia declarata cu extensia formatului detectat;
- daca numele devine gol, foloseste `photo` plus extensia detectata;
- rezultatul este numai metadata si nu participa la construirea path-ului fizic.

Adauga teste pentru path Windows, path Unix, caractere de control, nume gol, nume prea lung si extensie falsa.

Verificare pentru utilizator: ruleaza numai testele normalizatorului.

Opreste-te si asteapta aprobarea.
