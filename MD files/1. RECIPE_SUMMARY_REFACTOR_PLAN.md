# Plan pentru separarea sumarului de reteta completa

## Scop

In prezent, codul incarca si foloseste obiectul `Recipe` complet in aproape toate fluxurile, inclusiv in locuri unde sunt necesare doar informatii de sumar. Asta inseamna ca pentru listari, selectii si rezultate de cautare se incarca inutil `Ingredients` si `Steps`.

Obiectivul este sa separam clar:

- sumarul retetei: folosit pentru listari, selectii si rezultate de cautare;
- reteta completa: folosita doar acolo unde chiar avem nevoie de ingrediente si pasi.

Metodele de search existente trebuie pastrate ca flux/concept. Nu introducem metode noi de tip `SearchRecipeSummaries`. In schimb, eficientizam implementarea lor si schimbam rezultatul astfel incat search-ul sa intoarca sumar.

## Reguli de baza

1. Listarile folosesc doar sumar.
2. Selectiile folosesc doar sumar.
3. Search-ul cauta inclusiv in ingrediente si pasi.
4. Search-ul cauta si in note.
5. Rezultatul search-ului este doar sumar.
6. Detaliile si editarea incarca reteta completa dupa `Id`.
7. Delete-ul nu incarca reteta completa.
8. Backup export ramane pe retete complete.

## Model nou: `RecipeSummary`

Se adauga un model nou, de exemplu in `CarteDeBucate.App/Models/RecipeSummary.cs`.

Campuri propuse:

```csharp
public class RecipeSummary
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string SourceUrl { get; set; } = "";
    public DateTime SavedAt { get; set; }
    public RecipeStatus Status { get; set; }
    public int? UserId { get; set; }
}
```

Nu contine:

- `Ingredients`
- `Steps`
- `Notes`

Nota: `Notes` nu face parte din sumar, dar ramane camp cautabil in search.

## Etapa 1: Repository contract

Fisier: `CarteDeBucate.App/Data/Repositories/IRecipeRepository.cs`

### 1.1. Adaugam metode pentru sumar

Adaugam metode separate pentru listari:

```csharp
List<RecipeSummary> GetAllRecipeSummaries();
List<RecipeSummary> GetRecipeSummariesByUserId(int userId);
```

### 1.2. Pastram metodele complete

Metodele existente pentru retete complete raman disponibile:

```csharp
List<Recipe> GetAllRecipes();

Recipe? GetRecipeById(int recipeId);
Recipe? GetRecipeByIdAndUserId(int recipeId, int userId);
```

Ele vor fi folosite doar pentru cazurile care chiar au nevoie de ingrediente si pasi.

### 1.3. Pastram metoda de search existenta ca idee

Nu adaugam metode de tip:

```csharp
SearchRecipeSummaries(...)
```

In schimb, metoda existenta de search trebuie sa returneze sumar.

Semnatura aleasa pentru repository:

```csharp
List<RecipeSummary> SearchRecipes(string searchText, int? userId);
```

Motiv: repository-ul poate aplica filtrul de user direct in query, iar service-ul ramane responsabil cu `CurrentUserId`.

## Etapa 4: Implementare in database repository

Fisier: `CarteDeBucate.App/Data/Repositories/DatabaseRecipeRepository.cs`

## 4.1. Adaugam citire de sumar

Metodele de sumar trebuie sa faca doar query pe tabela `Recipes`.

Exemplu:

```sql
SELECT Id, Name, SourceUrl, SavedAt, Status, UserId
FROM Recipes
ORDER BY SavedAt DESC;
```

Pentru user:

```sql
SELECT Id, Name, SourceUrl, SavedAt, Status, UserId
FROM Recipes
WHERE UserId = @UserId
ORDER BY SavedAt DESC;
```

Nu se apeleaza:

- `GetIngredientsForRecipe`
- `GetStepsForRecipe`

### 4.2. Pastram full load pentru `GetRecipeById`

`GetRecipeById` si `GetRecipeByIdAndUserId` raman responsabile sa incarce:

- randul principal din `Recipes`;
- ingredientele;
- pasii.

### 4.3. Mutam search-ul in SQL

Pentru database, search-ul trebuie facut in baza de date, nu in memorie.

Motiv: evitam incarcarea tuturor retetelor, ingredientelor si pasilor doar pentru filtrare.

Search-ul trebuie sa caute in:

- `Recipes.Name`
- `Recipes.SourceUrl`
- `Recipes.Notes`
- `RecipeIngredients.IngredientText`
- `RecipeSteps.StepText`

Rezultatul trebuie sa fie doar `RecipeSummary`.

Forma recomandata:

```sql
SELECT DISTINCT r.Id, r.Name, r.SourceUrl, r.SavedAt, r.Status, r.UserId
FROM Recipes r
LEFT JOIN RecipeIngredients i ON i.RecipeId = r.Id
LEFT JOIN RecipeSteps s ON s.RecipeId = r.Id
WHERE (
    LOWER(r.Name) LIKE @SearchText
    OR LOWER(r.SourceUrl) LIKE @SearchText
    OR LOWER(COALESCE(r.Notes, '')) LIKE @SearchText
    OR LOWER(i.IngredientText) LIKE @SearchText
    OR LOWER(s.StepText) LIKE @SearchText
)
ORDER BY r.SavedAt DESC;
```

Pentru user, se adauga:

```sql
AND r.UserId = @UserId
```

Atentie la paranteze: filtrul de user trebuie aplicat peste tot, nu doar pe ultima conditie.

## Etapa 5: Implementare in JSON repository

Fisier: `CarteDeBucate.App/Data/Repositories/JsonRecipeRepository.cs`

### 5.1. Citirea JSON ramane completa intern

Pentru JSON nu putem evita complet incarcarea in memorie, pentru ca storage-ul este un fisier cu obiecte complete.

### 5.2. Listarea intoarce sumar

`GetAllRecipeSummaries`:

- citeste lista completa din fisier;
- proiecteaza fiecare `Recipe` la `RecipeSummary`;
- returneaza doar sumarul.

`GetRecipeSummariesByUserId`:

- citeste lista completa;
- filtreaza dupa `UserId`;
- proiecteaza la `RecipeSummary`.

### 5.3. Search-ul se face in memorie, dar rezultatul e sumar

Pentru JSON, `SearchRecipes`:

- citeste retetele complete;
- cauta in `Name`, `SourceUrl`, `Notes`, `Ingredients`, `Steps`;
- returneaza doar `RecipeSummary`.

## Etapa 9: Delete fara full load

In prezent, `RecipeImporterService.DeleteRecipe(int recipeId)` incarca reteta prin `GetRecipeById(recipeId)` ca sa verifice existenta si sa returneze `RecipeSaveResult.Success(..., recipe)`.

Pentru a evita full load la delete, sunt doua optiuni.

### Optiunea recomandata: verificare lightweight

Adaugam in repository:

```csharp
bool RecipeExistsById(int recipeId);
bool RecipeExistsByIdForUser(int recipeId, int userId);
```

`DeleteRecipe` devine:

1. valideaza `recipeId`;
2. verifica existenta fara ingrediente/pasi;
3. sterge;
4. returneaza succes.

Adaugam un factory separat pentru succes fara reteta:

```csharp
RecipeSaveResult.Success(string message)
```

Astfel, delete-ul poate returna doar mesajul de succes fara sa incarce reteta completa si fara sa construiasca o reteta minima artificiala.

### Optiune respinsa: delete direct si rezultat boolean

Nu schimbam repository delete sa intoarca `bool`:

```csharp
bool DeleteRecipe(int recipeId);
bool DeleteRecipeForUser(int recipeId, int userId);
```

Motiv: ar fi o schimbare mai mare in contractul repository. Decizia aleasa este verificarea lightweight cu `RecipeExistsById` / `RecipeExistsByIdForUser`.

## Rezultat final asteptat

Dupa refactorizare:

- listarea nu mai incarca ingrediente si pasi;
- selectia nu mai incarca ingrediente si pasi;
- search-ul cauta in ingrediente si pasi;
- search-ul intoarce doar sumar;
- database search ruleaza in SQL;

- detaliile si editarea incarca reteta completa doar dupa alegerea unui `Id`;
