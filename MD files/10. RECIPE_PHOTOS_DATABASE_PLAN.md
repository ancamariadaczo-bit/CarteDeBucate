# Plan 2 - Pregatirea bazei de date pentru fotografiile retetelor

## Scop

Adauga in Core persistenta SQLite a metadatelor fotografiilor asociate retetelor. Continutul binar al fotografiilor ramane in fisiere si nu se salveaza in baza de date.

Acest plan se executa dupa `MD files/9. BACKUP_VERSIONING_PLAN.md` si inainte de `MD files/11. RECIPE_PHOTO_SERVICE_PLAN.md`.

Prima implementare a fotografiilor este disponibila numai cand retetele folosesc `StorageMode.Database`. Modul JSON nu afiseaza si nu gestioneaza fotografii si nu primeste un repository foto separat.

## Starea curenta observata

- SQLite este initializat prin `DatabaseInitializer` si migrat prin `DatabaseMigrator`.
- Migrarile existente au versiunile 1, 2 si 3.
- `DatabaseScripts.CreateTables` creeaza schema completa pentru baze noi.
- Clasele SQLite isi construiesc separat connection string-ul.
- Repository-urile sunt in `CarteDeBucate.Core/Data/Repositories`.
- `Recipes.Id` este cheia retetei, iar reteta are optional `UserId`.
- Modul JSON nu initializeaza baza SQLite prin `AppServiceFactory.EnsureDatabaseIsUpToDate(AppSettings)`.
- Nu exista in prezent model, tabela sau repository pentru fotografii.

## Structura tinta

Enumul propus pentru provenienta fotografiei:

```csharp
public enum RecipePhotoOrigin
{
    Unspecified = 0,
    RecipeSource = 1,
    UserUpload = 2
}
```

Tabela tinta `RecipePhotos`:

```sql
CREATE TABLE IF NOT EXISTS RecipePhotos (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    RecipeId INTEGER NOT NULL,
    StorageFileName TEXT NOT NULL UNIQUE
        CHECK (length(trim(StorageFileName)) BETWEEN 1 AND 128),
    OriginalFileName TEXT NOT NULL
        CHECK (length(trim(OriginalFileName)) BETWEEN 1 AND 255),
    ContentType TEXT NOT NULL
        CHECK (length(trim(ContentType)) BETWEEN 1 AND 100),
    FileSize INTEGER NOT NULL
        CHECK (FileSize > 0),
    CreatedAtUtc TEXT NOT NULL,
    DisplayOrder INTEGER NOT NULL DEFAULT 0
        CHECK (DisplayOrder >= 0),
    Origin INTEGER NOT NULL DEFAULT 0,
    FOREIGN KEY (RecipeId)
        REFERENCES Recipes(Id)
        ON DELETE CASCADE
);
```

Indexul tinta:

```sql
CREATE INDEX IF NOT EXISTS IX_RecipePhotos_RecipeId_DisplayOrder_Id
ON RecipePhotos (RecipeId, DisplayOrder, Id);
```

Decizii:

- DB retine numai metadata si numele intern al fisierului, niciodata path absolut;
- `StorageFileName` este un simplu nume intern generat de serviciu, nu o valoare furnizata de utilizator;
- pot exista mai multe fotografii pentru o reteta;
- fotografia cu cel mai mic `DisplayOrder` este fotografia principala;
- fotografiile noi se adauga la sfarsit, iar `Id` este criteriul secundar de ordonare;
- nu exista coloana `IsPrimary` si nu exista constrangere unica pe `(RecipeId, DisplayOrder)`;
- `Origin` pastreaza provenienta, nu formatul fisierului;
- valorile enumului `RecipePhotoOrigin` sunt validate de serviciu si nu sunt limitate printr-un `CHECK` in DB;
- `CreatedAtUtc` este generat de serviciu, este intotdeauna UTC si se persista in format round-trip `"O"`;
- limita maxima a fisierului este o regula configurabila a serviciului si nu este duplicata intr-un `CHECK` DB;
- proprietarul fotografiei se valideaza prin reteta si `Recipes.UserId`, fara duplicarea lui `UserId` in tabela foto;
- `ON DELETE CASCADE` sterge metadata fotografiilor in aceeasi tranzactie cu reteta;
- serviciul foto va muta fisierele intr-o carantina de pe acelasi filesystem inaintea stergerii retetei, le va sterge definitiv dupa commit si le va restaura la esec;
- o reconciliere ulterioara va putea curata fisiere temporare sau orfane, dar nu se implementeaza in acest plan;
- serviciul foto din planul 3 va coordona filesystem-ul si metadata;
- suportul JSON pentru fotografii, daca va fi dorit, necesita un plan separat.

## Contractul repository-ului tinta

```csharp
void Add(RecipePhoto photo);
bool AddForUser(RecipePhoto photo, int userId);
RecipePhoto? GetById(int photoId);
RecipePhoto? GetByIdAndUserId(int photoId, int userId);
List<RecipePhoto> GetByRecipeId(int recipeId);
List<RecipePhoto> GetByRecipeIdAndUserId(int recipeId, int userId);
bool Delete(int photoId);
bool DeleteForUser(int photoId, int userId);
```

Reguli ale contractului:

- `Add` si `AddForUser` seteaza `photo.Id` dupa insert reusit;
- `AddForUser` verifica proprietarul si face insertul intr-un singur statement SQL;
- `AddForUser` intoarce `false` numai daca reteta nu exista sau nu apartine utilizatorului;
- `DeleteForUser` verifica proprietarul si sterge metadata intr-un singur statement SQL;
- metodele conditionate intorc `false` cand nu modifica niciun rand;
- erorile reale SQLite se propaga spre serviciu;
- citirile dupa id intorc `null` pentru un rezultat inexistent;
- listarile intorc o lista goala cand nu exista rezultate.
